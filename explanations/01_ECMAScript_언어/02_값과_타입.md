# 1.2. 값과 타입

값은 프로그램이 실행되는 동안 생성되고 전달되며 연산의 대상이 되는 데이터다.

```js
10;
("hello");
true;
null;
```

위 코드의 `10`, `"hello"`, `true`, `null`은 각각 서로 다른 종류의 값을 나타낸다.

데이터 타입(Data Type)은 이러한 값들을 성질과 동작 방식에 따라 분류한 것이다. JavaScript의 모든 값은 하나의 데이터 타입에 속한다.

ECMAScript의 언어 타입은 다음 여덟 가지다.

```txt
ECMAScript 언어 타입
├─ 원시 타입
│  ├─ Undefined
│  ├─ Null
│  ├─ Boolean
│  ├─ Number
│  ├─ BigInt
│  ├─ String
│  └─ Symbol
│
└─ Object
```

즉 JavaScript에는 일곱 개의 원시 타입과 하나의 객체 타입이 있다.

## 1.2.1 값과 타입

### 값

값은 JavaScript 프로그램이 실행되는 동안 다루는 실제 데이터다.

```js
10;
("hello");
true;
```

각 표현식을 평가하면 다음 값이 만들어진다.

```txt
10         Number 값
"hello"    String 값
true       Boolean 값
```

표현식과 값은 구별해야 한다.

```js
5 + 5;
```

```txt
5 + 5    덧셈 표현식
10       표현식을 평가한 결과인 Number 값
```

표현식은 소스 코드의 문법 구조이고, 값은 그 표현식이 평가된 뒤 프로그램 안에서 사용되는 데이터다.

### 타입

타입은 값이 어떤 종류에 속하며, 그 값에 어떤 연산을 적용할 수 있는지를 나타낸다.

```js
10 + 20;
```

두 Number 값을 더하면 Number 값 `30`이 만들어진다.

```js
"10" + "20";
```

두 String 값을 `+`로 연결하면 String 값 `"1020"`이 만들어진다.

```js
10n + 20n;
```

두 BigInt 값을 더하면 BigInt 값 `30n`이 만들어진다.

같은 `+` 토큰을 사용하더라도 피연산자의 타입에 따라 수행되는 동작이 달라질 수 있다.

### 값과 바인딩의 구별

다음 코드에서 `value`는 값이 아니라 바인딩을 참조하는 이름이다.

```js
let value = 10;
```

관계는 다음과 같다.

```txt
value    바인딩을 참조하는 식별자
10       Number 값
```

이후 다른 타입의 값을 다시 연결할 수도 있다.

```js
let value = 10;

value = "hello";
value = true;
```

```txt
처음 value에 연결된 값    Number 값 10
다음에 연결된 값          String 값 "hello"
마지막에 연결된 값        Boolean 값 true
```

JavaScript에서는 일반적인 변수 바인딩에 하나의 고정된 데이터 타입이 부여되지 않는다. 값이 타입을 가지며, 바인딩은 실행 중 서로 다른 타입의 값과 다시 연결될 수 있다.

이를 흔히 JavaScript가 동적 타입 언어라고 표현한다.

### 타입은 값의 동작을 결정한다

타입에 따라 허용되는 연산과 그 결과가 달라진다.

```js
1 + 2; // 3
"1" + "2"; // "12"
1n + 2n; // 3n
```

타입이 맞지 않으면 오류가 발생할 수도 있다.

```js
1n + 2; // TypeError
```

BigInt 값과 Number 값은 산술 연산에서 자동으로 하나의 숫자 타입으로 통합되지 않는다.

### `typeof` 연산자

`typeof`는 피연산자의 종류를 나타내는 문자열을 반환하는 단항 연산자다.

```js
typeof 10; // "number"
typeof 10n; // "bigint"
typeof "hello"; // "string"
typeof true; // "boolean"
typeof undefined; // "undefined"
typeof Symbol(); // "symbol"
```

객체에는 일반적으로 `"object"`를 반환한다.

```js
typeof {}; // "object"
typeof []; // "object"
typeof new Date(); // "object"
```

함수 객체에는 `"function"`을 반환한다.

```js
typeof function () {}; // "function"
```

다만 함수는 별도의 ECMAScript 언어 타입이 아니다. 호출할 수 있는 특별한 객체다.

`null`에는 `"object"`가 반환된다.

```js
typeof null; // "object"
```

그러나 `null`은 객체가 아니라 Null 타입의 원시값이다. 이는 JavaScript 초기부터 유지된 `typeof`의 특수한 동작이다.

따라서 `typeof`의 반환 문자열과 ECMAScript의 정확한 언어 타입 분류는 완전히 일치하지 않는다.

## 1.2.2 원시값

원시값은 객체가 아닌 값이다.

```txt
원시값
├─ undefined
├─ null
├─ boolean
├─ number
├─ bigint
├─ string
└─ symbol
```

원시값에는 다음과 같은 공통적인 성질이 있다.

```txt
객체가 아니다
고유한 프로퍼티를 직접 저장하지 않는다
값 자체를 변경할 수 없다
값 자체를 기준으로 비교할 수 있다
```

### 원시값은 변경할 수 없다

원시값은 불변(immutable)이다. 한 번 만들어진 원시값 자체의 내부 내용을 변경할 수 없다.

```js
let value = "hello";

value = "world";
```

위 코드에서 기존 문자열 `"hello"`가 `"world"`로 변한 것이 아니다.

```txt
처음
value → "hello"

재할당 후
value → "world"
```

바인딩 `value`가 다른 문자열 값과 다시 연결된 것이다.

불리언이나 숫자도 마찬가지다.

```js
let count = 1;

count = count + 1;
```

숫자 값 `1` 자체가 `2`로 변한 것이 아니다.

```txt
1을 읽음
→ 1 + 1을 계산
→ 새로운 Number 값 2 생성
→ count를 2와 다시 연결
```

### 원시값의 프로퍼티 접근

문자열은 원시값이지만 다음과 같이 프로퍼티나 메서드에 접근할 수 있다.

```js
const text = "hello";

text.length; // 5
text.toUpperCase(); // "HELLO"
```

이 때문에 문자열이 객체처럼 보일 수 있다.

그러나 `text`가 String 객체로 바뀐 것은 아니다. 원시값에 프로퍼티 접근이 일어날 때 JavaScript가 해당 원시값에 대응하는 객체 기능을 일시적으로 사용할 수 있게 처리한다.

```txt
String 원시값
→ 프로퍼티 접근을 위해 String 관련 객체 동작 사용
→ 프로퍼티나 메서드 결과 반환
```

Boolean, Number, BigInt, String, Symbol에는 대응하는 내장 객체가 있다.

```js
Boolean;
Number;
BigInt;
String;
Symbol;
```

이들은 원시 타입 자체와 구별해야 한다.

```js
typeof "hello"; // "string"
typeof new String("hello"); // "object"
```

`"hello"`는 String 원시값이고, `new String("hello")`는 String 값을 감싼 객체다.

### Undefined 타입

Undefined 타입은 `undefined` 하나의 값만 가진다.

```js
undefined;
```

`undefined`는 보통 어떤 값이 아직 지정되지 않았거나, 연산 결과로 제공할 값이 없음을 나타낸다.

#### 초기화되지 않은 `let` 바인딩의 실행 후 값

```js
let value;

console.log(value); // undefined
```

`let value;` 선언이 실행되면 `value` 바인딩은 `undefined`로 초기화된다.

#### 존재하지 않는 프로퍼티를 읽은 결과

```js
const user = {
  name: "Mars",
};

console.log(user.age); // undefined
```

`age`라는 프로퍼티가 없으므로 프로퍼티 접근 결과로 `undefined`가 반환된다.

#### 반환 표현식이 없는 함수

```js
function run() {}

const result = run();

console.log(result); // undefined
```

함수가 별도의 값을 반환하지 않고 정상적으로 끝나면 호출 결과는 `undefined`다.

```js
function run() {
  return;
}
```

명시적으로 값 없이 `return`해도 결과는 `undefined`다.

#### 생략된 함수 인수

```js
function print(value) {
  console.log(value);
}

print(); // undefined
```

인수를 전달하지 않은 매개변수에는 일반적으로 `undefined`가 연결된다.

#### `undefined`는 리터럴이 아니다

```js
undefined;
```

`undefined`는 `null`, `true`, `false`와 같은 리터럴 문법이 아니다. `undefined`라는 이름을 참조하는 식별자 참조다.

현대 JavaScript의 전역 `undefined` 프로퍼티는 덮어쓸 수 없지만, 내부 스코프에서 같은 이름의 바인딩을 선언할 수는 있다.

```js
function run(undefined) {
  console.log(undefined);
}

run("custom"); // "custom"
```

따라서 반드시 실제 Undefined 값을 만들고 싶다면 다음과 같이 `void` 연산자를 사용할 수도 있다.

```js
void 0; // undefined
```

### Null 타입

Null 타입은 `null` 하나의 값만 가진다.

```js
null;
```

`null`은 값이 존재하지 않는 상태를 개발자가 명시적으로 표현할 때 주로 사용한다.

```js
const selectedUser = null;
```

이는 대략 다음과 같은 의도를 나타낼 수 있다.

```txt
selectedUser라는 값의 자리는 존재한다
현재 선택된 사용자는 없다
```

#### `undefined`와 `null`

두 값 모두 값의 부재와 관련되지만 일반적인 사용 의도에는 차이가 있다.

```txt
undefined
값이 아직 정해지지 않았거나
연산 결과가 제공되지 않은 상태

null
값이 없다는 상태를 코드에서 의도적으로 지정
```

예를 들어 다음 객체에서 `middleName`은 명시적으로 없음을 나타내고, `age`는 프로퍼티 자체가 존재하지 않는다.

```js
const user = {
  name: "Mars",
  middleName: null,
};

user.middleName; // null
user.age; // undefined
```

다만 이러한 의미 구분은 언어가 강제로 보장하는 규칙은 아니다. 프로그램의 설계에 따라 `null`과 `undefined`의 사용 기준을 정해야 한다.

#### `typeof null`

```js
typeof null; // "object"
```

결과는 `"object"`지만 `null`은 객체가 아니다. Null 타입의 원시값이다.

`null`인지 정확하게 확인하려면 직접 비교할 수 있다.

```js
value === null;
```

### Boolean 타입

Boolean 타입은 두 개의 값만 가진다.

```txt
true
false
```

```js
const isLoggedIn = true;
const isAdmin = false;
```

불리언 값은 조건의 참과 거짓을 표현한다.

```js
if (isLoggedIn) {
  showDashboard();
}
```

비교 연산의 결과도 Boolean 값이다.

```js
10 > 5; // true
10 === 20; // false
```

논리 부정 연산자는 값을 Boolean으로 변환한 뒤 결과를 반대로 만든다.

```js
!true; // false
!false; // true
```

JavaScript의 조건식에는 Boolean 값만 들어갈 수 있는 것은 아니다.

```js
if ("hello") {
  console.log("실행됨");
}
```

조건 위치에 다른 타입의 값이 들어오면 내부적으로 불리언 변환이 수행된다.

### Number 타입

Number 타입은 정수와 실수를 하나의 타입으로 표현한다.

```js
10;
-5;
3.14;
1e3;
```

```js
typeof 10; // "number"
typeof 3.14; // "number"
```

JavaScript에는 일반적인 정수 전용 Number 타입과 실수 전용 Number 타입이 따로 존재하지 않는다.

```txt
10       Number
3.14     Number
-200     Number
```

#### 정수와 실수 표기의 차이

다음 두 값은 문법 표기는 다르지만 같은 Number 값이다.

```js
10 === 10.0; // true
```

```txt
10      정수처럼 적은 숫자 리터럴
10.0    실수처럼 적은 숫자 리터럴

평가 결과
→ 같은 Number 값
```

#### 부동소수점 정밀도

Number 값은 유한한 정밀도로 숫자를 표현한다. 따라서 일부 십진 소수는 정확하게 표현되지 않는다.

```js
0.1 + 0.2; // 0.30000000000000004
```

이는 JavaScript만의 단순한 계산 오류가 아니라, 이진 부동소수점 표현에서 `0.1`과 `0.2`를 유한한 자리로 정확히 나타낼 수 없기 때문에 생긴다.

#### 안전한 정수 범위

Number 타입으로 모든 정수를 무한히 정확하게 표현할 수 있는 것은 아니다.

```js
Number.MAX_SAFE_INTEGER;
// 9007199254740991
```

안전한 정수 범위 밖에서는 서로 다른 정수가 같은 Number 값으로 표현될 수 있다.

```js
Number.MAX_SAFE_INTEGER + 1 === Number.MAX_SAFE_INTEGER + 2;
// true
```

정확한 큰 정수 계산이 필요하면 BigInt를 고려할 수 있다.

#### `NaN`

`NaN`은 Not-a-Number라는 이름을 가지지만 Number 타입의 값이다.

```js
typeof NaN; // "number"
```

숫자로 계산할 수 없는 연산에서 만들어질 수 있다.

```js
Number("hello"); // NaN
0 / 0; // NaN
```

`NaN`은 자기 자신과도 같지 않다.

```js
NaN === NaN; // false
```

`NaN` 여부는 다음과 같이 확인할 수 있다.

```js
Number.isNaN(value);
```

#### `Infinity`와 `-Infinity`

Number 타입에는 양의 무한대와 음의 무한대를 나타내는 값이 있다.

```js
Infinity;
-Infinity;
```

```js
1 / 0; // Infinity
-1 / 0; // -Infinity
```

```js
typeof Infinity; // "number"
```

#### 양의 0과 음의 0

Number 타입에는 `+0`과 `-0`이 존재한다.

```js
const positiveZero = 0;
const negativeZero = -0;
```

엄격한 동등 비교에서는 같다고 판단한다.

```js
0 === -0; // true
```

그러나 일부 연산에서는 구별된다.

```js
1 / 0; // Infinity
1 / -0; // -Infinity
```

---

### BigInt 타입

BigInt 타입은 임의 정밀도의 정수를 나타내기 위한 원시 타입이다.

```js
10n;
123456789012345678901234567890n;
```

리터럴 뒤의 `n`은 BigInt 값이라는 뜻이다.

```js
typeof 10n; // "bigint"
```

`BigInt` 함수를 이용해 만들 수도 있다.

```js
BigInt(10); // 10n
BigInt("123456"); // 123456n
```

#### 정수만 표현한다

BigInt는 정수만 나타낸다.

```js
1.5n; // SyntaxError
```

나눗셈 결과에 소수 부분이 생기면 버려진다.

```js
5n / 2n; // 2n
```

#### Number와 직접 섞어 산술 연산할 수 없다

```js
1n + 1; // TypeError
```

타입을 명시적으로 맞춰야 한다.

```js
1n + BigInt(1); // 2n
```

또는 BigInt를 Number로 변환할 수 있다.

```js
Number(1n) + 1; // 2
```

다만 큰 BigInt를 Number로 변환하면 정밀도를 잃을 수 있다.

#### `NaN`과 `Infinity`가 없다

BigInt는 정수만 나타내므로 Number 타입에 있는 `NaN`, `Infinity`, `-Infinity`에 대응하는 BigInt 값이 없다.

---

### String 타입

String 타입은 텍스트를 나타내는 원시 타입이다.

```js
"hello";
"hello";
`hello`;
```

```js
typeof "hello"; // "string"
```

#### UTF-16 코드 단위의 순서

JavaScript의 문자열은 명세상 UTF-16 코드 단위의 순서로 구성된다.

대부분의 일반 문자는 하나의 코드 단위로 표현된다.

```js
"A".length; // 1
```

일부 문자는 두 개의 UTF-16 코드 단위로 표현된다.

```js
"😀".length; // 2
```

사람이 보는 문자 수와 문자열의 `length`가 항상 일치하지 않는 이유다.

#### 문자열은 불변이다

문자열 값 자체의 문자를 변경할 수 없다.

```js
const text = "hello";

text[0] = "H";

console.log(text); // "hello"
```

새 문자열을 만들어 바인딩을 다시 연결해야 한다.

```js
let text = "hello";

text = "H" + text.slice(1);

console.log(text); // "Hello"
```

#### 문자열 연결

`+` 연산자는 피연산자 중 문자열이 포함된 상황에서 문자열 연결을 수행할 수 있다.

```js
"hello" + " world"; // "hello world"
```

다른 타입의 값이 문자열로 변환될 수도 있다.

```js
"count: " + 10; // "count: 10"
```

#### 문자열 인덱스 접근

```js
const text = "hello";

text[0]; // "h"
text[1]; // "e"
```

문자열의 인덱스 접근 결과 역시 길이 1인 String 값이다.

JavaScript에는 별도의 문자(Character) 원시 타입이 없다.

---

### Symbol 타입

Symbol 타입은 서로 겹치지 않는 고유한 원시값을 나타낸다.

```js
const first = Symbol();
const second = Symbol();

first === second; // false
```

`Symbol()`을 호출할 때마다 새로운 Symbol 값이 만들어진다.

```js
Symbol() === Symbol(); // false
```

#### Symbol의 인수

`Symbol()`에는 선택적으로 설명을 전달할 수 있다.

```js
const key = Symbol("userId");
```

`"userId"`는 생성되는 Symbol 값의 설명이다. Symbol 값의 고유성을 결정하는 이름이 아니다.

```js
const first = Symbol("id");
const second = Symbol("id");

first === second; // false
```

두 Symbol에 같은 설명이 들어갔지만 각각의 `Symbol()` 호출이 서로 다른 값을 만들었다.

```txt
Symbol("id") 첫 번째 호출
→ 첫 번째 고유한 Symbol 값

Symbol("id") 두 번째 호출
→ 두 번째 고유한 Symbol 값
```

설명은 디버깅이나 출력에서 사람이 용도를 알아보기 쉽게 하기 위한 정보다.

```js
const key = Symbol("userId");

key.description; // "userId"
String(key); // "Symbol(userId)"
```

#### 객체의 프로퍼티 키로 사용

객체의 프로퍼티 키는 String 또는 Symbol 값일 수 있다.

```js
const internalId = Symbol("internalId");

const user = {
  name: "Mars",
  [internalId]: 100,
};
```

```js
user.name; // "Mars"
user[internalId]; // 100
```

다른 코드가 같은 문자열 설명으로 Symbol을 만들어도 서로 다른 프로퍼티 키가 된다.

```js
const firstKey = Symbol("id");
const secondKey = Symbol("id");

const object = {
  [firstKey]: 10,
  [secondKey]: 20,
};

object[firstKey]; // 10
object[secondKey]; // 20
```

Symbol은 여러 코드가 같은 객체에 프로퍼티를 추가할 때 우연히 같은 문자열 키를 사용하여 충돌하는 문제를 피하는 데 사용할 수 있다.

#### Symbol은 비밀 키가 아니다

Symbol 프로퍼티는 일반적인 문자열 키 열거에서 제외될 수 있다.

```js
const key = Symbol("internal");

const object = {
  visible: 10,
  [key]: 20,
};

Object.keys(object); // ["visible"]
```

하지만 완전히 숨겨지는 것은 아니다.

```js
Object.getOwnPropertySymbols(object);
// [Symbol(internal)]

Reflect.ownKeys(object);
// ["visible", Symbol(internal)]
```

따라서 Symbol은 보안이나 완전한 private 기능을 위한 수단이 아니다.

#### 전역 Symbol 레지스트리

`Symbol.for()`는 문자열 키를 사용하여 전역 Symbol 레지스트리에서 Symbol을 찾거나 등록한다.

```js
const first = Symbol.for("shared");
const second = Symbol.for("shared");

first === second; // true
```

일반 `Symbol()`과 차이가 있다.

```js
Symbol("shared") === Symbol("shared"); // false
Symbol.for("shared") === Symbol.for("shared"); // true
```

#### Well-known Symbol

JavaScript에는 언어의 특정 동작을 연결하기 위해 미리 정의된 Symbol 값들이 있다.

```js
Symbol.iterator;
Symbol.toPrimitive;
Symbol.toStringTag;
Symbol.hasInstance;
```

예를 들어 `Symbol.iterator`는 객체가 반복될 때 사용할 동작을 지정하는 프로퍼티 키다.

```js
const values = {
  *[Symbol.iterator]() {
    yield 1;
    yield 2;
    yield 3;
  },
};

for (const value of values) {
  console.log(value);
}
```

Symbol은 객체 프로퍼티 키 충돌을 피하는 용도뿐 아니라, JavaScript 언어와 객체의 특별한 동작을 연결하는 용도로도 사용된다.

---

## 1.2.3 객체값

객체값은 프로퍼티를 가질 수 있으며, 각 객체가 고유한 정체성을 가지는 값이다.

```js
const user = {
  name: "Mars",
  age: 20,
};
```

객체는 단순히 여러 원시값을 하나로 묶은 자료만을 의미하지 않는다.

객체에는 다음과 같은 요소가 연결될 수 있다.

```txt
객체
├─ 프로퍼티
├─ 프로토타입
├─ 내부 슬롯
├─ 내부 메서드
└─ 객체 고유의 정체성
```

객체의 세부 구조와 프로퍼티 동작은 `1.5 객체 모델`에서 별도로 다룬다.

### 객체는 고유한 정체성을 가진다

모양과 내용이 같은 두 객체를 각각 만들더라도 서로 다른 객체다.

```js
const first = {
  value: 10,
};

const second = {
  value: 10,
};

first === second; // false
```

두 객체의 프로퍼티 구성이 같아도 각각 별도로 생성된 객체이기 때문이다.

```txt
first  → 첫 번째 객체
second → 두 번째 객체
```

같은 객체값을 공유하면 같다고 판단된다.

```js
const first = {
  value: 10,
};

const second = first;

first === second; // true
```

```txt
first  ─┐
        ├→ 같은 객체
second ─┘
```

### 객체는 변경될 수 있다

일반적인 객체는 생성된 뒤 프로퍼티를 추가하거나 변경하거나 삭제할 수 있다.

```js
const user = {
  name: "Mars",
};

user.age = 20;
user.name = "Ares";
delete user.age;
```

이는 원시값이 불변인 것과 다른 성질이다.

```txt
원시값
값 자체를 변경할 수 없음

객체값
동일한 객체의 상태가 변경될 수 있음
```

다만 모든 객체가 항상 자유롭게 변경 가능한 것은 아니다. 프로퍼티 서술자나 `Object.freeze()` 등의 기능으로 변경을 제한할 수 있다.

### 프로퍼티의 값

객체의 프로퍼티에는 모든 종류의 JavaScript 값을 저장할 수 있다.

```js
const object = {
  undefinedValue: undefined,
  nullValue: null,
  booleanValue: true,
  numberValue: 10,
  bigintValue: 10n,
  stringValue: "hello",
  symbolValue: Symbol("value"),
  objectValue: {},
  functionValue() {},
};
```

### 프로퍼티 키

일반 객체의 프로퍼티 키는 String 또는 Symbol 값이다.

```js
const symbolKey = Symbol("key");

const object = {
  name: "Mars",
  [symbolKey]: 10,
};
```

숫자처럼 작성한 프로퍼티 키도 일반적으로 문자열 키가 된다.

```js
const object = {
  10: "value",
};

Object.keys(object); // ["10"]
```

```js
object[10]; // "value"
object["10"]; // "value"
```

### 배열도 객체다

```js
const values = [10, 20, 30];

typeof values; // "object"
```

배열은 요소의 순서와 `length`를 특별한 방식으로 관리하는 객체다.

```js
values[0]; // 10
values.length; // 3
```

일반적인 객체 여부만 확인하는 `typeof`로는 배열을 구별할 수 없다.

```js
Array.isArray(values); // true
```

### 함수도 객체다

```js
function run() {}

typeof run; // "function"
```

`typeof`는 `"function"`을 반환하지만 함수는 Object 타입에 속한다.

함수 객체는 일반 객체처럼 프로퍼티를 가질 수 있다.

```js
function run() {}

run.description = "실행 함수";

console.log(run.description); // "실행 함수"
```

함수 객체에는 일반 객체의 동작뿐 아니라 호출할 수 있는 내부 동작이 추가되어 있다.

```txt
함수 객체
├─ 객체로서 프로퍼티를 가짐
└─ 함수로서 호출될 수 있음
```

### 다양한 내장 객체

다음 값들도 모두 Object 타입이다.

```js
[];
new Date();
new Map();
new Set();
/pattern/;
Promise.resolve();
```

이 값들은 같은 Object 타입에 속하지만 서로 다른 내부 동작을 가진 객체 종류다.

```txt
Object 타입
├─ 일반 객체
├─ 함수 객체
├─ 배열 객체
├─ Date 객체
├─ RegExp 객체
├─ Map 객체
├─ Set 객체
├─ Promise 객체
└─ 기타 내장·호스트 객체
```

### 원시값과 래퍼 객체

다음 두 값은 서로 다르다.

```js
const primitive = "hello";
const wrapper = new String("hello");
```

```js
typeof primitive; // "string"
typeof wrapper; // "object"
```

```js
primitive === wrapper; // false
```

`primitive`은 String 원시값이고, `wrapper`는 String 값을 내부에 보관하는 객체다.

Boolean과 Number에도 비슷한 래퍼 객체가 있다.

```js
new Boolean(false);
new Number(10);
new String("hello");
```

래퍼 객체는 조건식에서 객체이므로 항상 참으로 변환되는 점을 주의해야 한다.

```js
if (new Boolean(false)) {
  console.log("실행됨");
}
```

`new Boolean(false)`는 내부 값이 `false`이더라도 객체이므로 truthy다.

일반적으로 원시값이 필요한 상황에서 래퍼 객체를 직접 생성할 필요는 거의 없다.

## 1.2.4 동일성 비교

JavaScript에는 두 값의 동일성을 판단하는 여러 방식이 있다.

대표적으로 다음이 있다.

```txt
느슨한 동등 비교       ==
엄격한 동등 비교       ===
SameValue 비교         Object.is()
SameValueZero 비교     Map, Set, includes 등의 내부 비교
```

각 비교 방식은 대부분 비슷하지만 `타입 변환`, `NaN`, `+0`, `-0`의 처리에서 차이가 있다.

---

### 엄격한 동등 비교

엄격한 동등 연산자는 `===`다.

```js
left === right;
```

일반적으로 타입 변환 없이 두 값을 비교한다.

#### 타입이 다르면 같지 않다

```js
10 === "10"; // false
true === 1; // false
null === undefined; // false
```

#### 같은 원시 타입은 값의 내용을 비교한다

```js
10 === 10; // true
"hello" === "hello"; // true
true === true; // true
10n === 10n; // true
```

Symbol은 같은 Symbol 값일 때만 같다.

```js
const symbol = Symbol("key");

symbol === symbol; // true
Symbol("key") === Symbol("key"); // false
```

#### 객체는 정체성을 비교한다

```js
{} === {}; // false
[] === []; // false
```

각 객체 리터럴 평가가 새로운 객체를 만들기 때문이다.

```js
const first = {};
const second = first;

first === second; // true
```

두 바인딩이 같은 객체값을 공유하므로 같다.

#### `NaN`

```js
NaN === NaN; // false
```

엄격한 동등 비교에서는 `NaN`은 모든 값과 같지 않으며 자기 자신과도 같지 않다.

#### 양의 0과 음의 0

```js
0 === -0; // true
```

엄격한 동등 비교는 `+0`과 `-0`을 같다고 판단한다.

---

### 느슨한 동등 비교

느슨한 동등 연산자는 `==`다.

```js
left == right;
```

두 값의 타입이 다르면 정해진 규칙에 따라 타입 변환을 수행한 뒤 비교할 수 있다.

```js
10 == "10"; // true
```

문자열 `"10"`이 숫자 비교를 위해 Number 값 `10`으로 변환된다.

```js
true == 1; // true
```

Boolean 값 `true`가 Number 값 `1`로 변환된다.

#### `null`과 `undefined`

느슨한 동등 비교에서는 서로 같다고 판단된다.

```js
null == undefined; // true
```

그러나 다른 대부분의 값과는 같지 않다.

```js
null == 0; // false
undefined == 0; // false
```

#### 예측하기 어려운 변환

```js
"" == 0; // true
"0" == false; // true
[] == 0; // true
```

느슨한 동등 비교는 여러 단계의 타입 변환을 포함할 수 있어, 코드를 읽는 사람이 결과를 즉시 판단하기 어려울 수 있다.

따라서 타입 변환을 의도하지 않는 일반적인 비교에는 `===`를 사용하는 경우가 많다.

다만 `==`가 임의로 동작하는 것은 아니다. ECMAScript 명세에 정의된 추상 동등 비교 알고리즘에 따라 동작한다.

---

### `Object.is()`

`Object.is()`는 SameValue 방식으로 두 값을 비교한다.

```js
Object.is(left, right);
```

대부분의 값에서는 `===`와 같은 결과를 낸다.

```js
Object.is(10, 10); // true
Object.is("hello", "hello"); // true
Object.is({}, {}); // false
```

차이는 `NaN`과 부호가 다른 0이다.

```js
Object.is(NaN, NaN); // true
```

```js
Object.is(0, -0); // false
```

비교하면 다음과 같다.

      <td><code>true</code></td>
    </tr>
    <tr>
      <td><code>0</code>과 <code>-0</code></td>

      <td><code>false</code></td>
    </tr>

</table>

### SameValueZero

SameValueZero는 다음과 같이 비교한다.

```txt
NaN과 NaN       같음
+0과 -0         같음
나머지          엄격한 동등 비교와 대체로 동일
```

직접 호출하는 전역 함수나 연산자는 없지만 여러 내장 기능에서 사용된다.

```js
[NaN].includes(NaN); // true
```

`Array.prototype.includes()`는 SameValueZero 비교를 사용하므로 `NaN`을 찾을 수 있다.

반면 `indexOf()`는 `NaN`을 찾지 못한다.

```js
[NaN].indexOf(NaN); // -1
```

Map과 Set의 키 비교에도 SameValueZero가 사용된다.

```js
const set = new Set();

set.add(NaN);
set.has(NaN); // true
```

## 1.2.5 타입 변환

타입 변환은 어떤 값을 다른 타입의 값으로 바꾸는 과정이다.

```js
Number("10"); // 10
String(10); // "10"
Boolean(1); // true
```

타입 변환은 크게 명시적 변환과 암시적 변환으로 나눌 수 있다.

```txt
명시적 타입 변환
코드에서 변환 의도를 직접 표현

암시적 타입 변환
연산을 수행하는 과정에서 언어가 자동으로 변환
```

---

### 명시적 타입 변환

개발자가 변환 함수를 직접 호출하여 타입을 바꾸는 방식이다.

```js
Number("10"); // 10
String(10); // "10"
Boolean(0); // false
BigInt("10"); // 10n
```

변환 의도가 소스 코드에 드러난다.

```js
const input = "100";
const amount = Number(input);
```

---

### 암시적 타입 변환

연산자가 요구하는 타입에 맞추기 위해 JavaScript가 자동으로 값을 변환하는 방식이다.

```js
"10" * 2; // 20
```

곱셈은 숫자 연산을 수행하므로 문자열 `"10"`이 Number 값 `10`으로 변환된다.

```txt
"10"
→ Number 변환
→ 10
→ 10 * 2
→ 20
```

`+`는 문자열 연결에도 사용되므로 결과가 달라질 수 있다.

```js
"10" + 2; // "102"
```

```txt
"10"이 문자열
→ 2를 문자열 "2"로 변환
→ 문자열 연결
→ "102"
```

조건문에서도 암시적 변환이 일어난다.

```js
if ("hello") {
  run();
}
```

문자열 `"hello"`가 Boolean 값 `true`에 해당하는 것으로 변환되어 본문이 실행된다.

---

### 추상 연산

ECMAScript 명세는 타입 변환 동작을 여러 추상 연산으로 정의한다.

대표적으로 다음이 있다.

```txt
ToPrimitive
ToBoolean
ToNumber
ToNumeric
ToString
ToPropertyKey
ToObject
```

이 이름들은 일반적으로 JavaScript 코드에서 직접 호출하는 함수가 아니다. 언어의 연산자가 값을 어떻게 변환해야 하는지를 설명하기 위한 명세상의 알고리즘이다.

---

### `ToPrimitive`

`ToPrimitive`는 입력값을 객체가 아닌 원시값으로 변환하는 추상 연산이다.

원시값이 입력되면 그대로 반환한다.

```txt
Number 원시값 → 그대로 Number 값
String 원시값 → 그대로 String 값
Symbol 원시값 → 그대로 Symbol 값
```

객체가 입력되면 객체를 대표할 원시값을 얻으려 한다.

```js
const object = {
  valueOf() {
    return 10;
  },
};

object + 5; // 15
```

개념적으로 다음 과정이 포함된다.

```txt
object
→ 원시값으로 변환 시도
→ valueOf()가 Number 값 10 반환
→ 10 + 5
→ 15
```

객체에 `Symbol.toPrimitive` 메서드가 있으면 이를 우선 사용할 수 있다.

```js
const object = {
  [Symbol.toPrimitive](hint) {
    if (hint === "number") {
      return 10;
    }

    return "object";
  },
};

Number(object); // 10
String(object); // "object"
```

변환을 요청한 문맥에 따라 `number`, `string`, `default` 등의 힌트가 전달될 수 있다.

---

### `ToBoolean`

`ToBoolean`은 값을 Boolean 값으로 변환한다.

다음 값들은 `false`로 변환된다.

```txt
false
undefined
null
+0
-0
0n
NaN
빈 문자열 ""
```

이들을 흔히 falsy 값이라고 부른다.

```js
Boolean(false); // false
Boolean(undefined); // false
Boolean(null); // false
Boolean(0); // false
Boolean(-0); // false
Boolean(0n); // false
Boolean(NaN); // false
Boolean(""); // false
```

그 외의 값은 모두 `true`로 변환된다.

```js
Boolean("0"); // true
Boolean("false"); // true
Boolean([]); // true
Boolean({}); // true
Boolean(function () {}); // true
```

빈 배열과 빈 객체도 객체이므로 truthy다.

```js
if ([]) {
  console.log("실행됨");
}
```

---

### `ToNumber`

`ToNumber`는 값을 Number 값으로 변환한다.

대표적인 변환 결과는 다음과 같다.

<table>
  <thead>
    <tr>
      <th>입력값</th>
      <th>Number 변환 결과</th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td><code>undefined</code></td>
      <td><code>NaN</code></td>
    </tr>
    <tr>
      <td><code>null</code></td>
      <td><code>0</code></td>
    </tr>
    <tr>
      <td><code>true</code></td>
      <td><code>1</code></td>
    </tr>
    <tr>
      <td><code>false</code></td>
      <td><code>0</code></td>
    </tr>
    <tr>
      <td><code>""</code></td>
      <td><code>0</code></td>
    </tr>
    <tr>
      <td><code>"10"</code></td>
      <td><code>10</code></td>
    </tr>
    <tr>
      <td><code>"hello"</code></td>
      <td><code>NaN</code></td>
    </tr>
  </tbody>
</table>

```js
Number(undefined); // NaN
Number(null); // 0
Number(true); // 1
Number(false); // 0
Number(""); // 0
Number("10"); // 10
Number("hello"); // NaN
```

Symbol 값은 Number로 변환할 수 없다.

```js
Number(Symbol()); // TypeError
```

BigInt는 `Number()` 함수를 이용해 명시적으로 변환할 수 있다.

```js
Number(10n); // 10
```

그러나 큰 BigInt 값은 Number의 정밀도 범위를 벗어날 수 있다.

---

### `ToNumeric`

`ToNumeric`은 숫자 연산에서 사용할 Number 또는 BigInt 값을 얻는 추상 연산이다.

```txt
입력값이 BigInt
→ BigInt로 유지

그 외 숫자로 변환 가능한 값
→ Number로 변환
```

이 과정은 Number와 BigInt가 서로 다른 숫자 타입으로 유지되는 이유와 관련된다.

```js
1n + 2n; // 3n
1 + 2; // 3
```

산술 연산에서 한쪽이 Number이고 다른 쪽이 BigInt이면 일반적으로 TypeError가 발생한다.

```js
1n + 2; // TypeError
```

두 타입을 자동으로 하나로 통합하면 정밀도를 유지할지, 부동소수점 계산을 허용할지 명확하지 않기 때문에 명시적인 변환이 요구된다.

---

### `ToString`

`ToString`은 값을 String 값으로 변환한다.

```js
String(undefined); // "undefined"
String(null); // "null"
String(true); // "true"
String(10); // "10"
String(10n); // "10"
```

배열과 객체도 원시값 변환을 거쳐 문자열이 될 수 있다.

```js
String([1, 2, 3]); // "1,2,3"
String({}); // "[object Object]"
```

Symbol은 일반적인 암시적 문자열 변환에서 오류가 발생할 수 있다.

```js
const symbol = Symbol("id");

"key: " + symbol; // TypeError
```

명시적으로 `String()`을 사용하면 문자열 표현을 얻을 수 있다.

```js
String(symbol); // "Symbol(id)"
```

---

### `ToPropertyKey`

객체의 프로퍼티 키로 사용할 값을 String 또는 Symbol 값으로 변환하는 추상 연산이다.

```js
const object = {};

object[10] = "value";
```

숫자 `10`은 문자열 키 `"10"`으로 변환된다.

```js
object[10]; // "value"
object["10"]; // "value"
```

Symbol 값은 문자열로 변환되지 않고 그대로 Symbol 프로퍼티 키가 된다.

```js
const key = Symbol("key");

object[key] = "symbol value";
```

```txt
프로퍼티 키 변환

Symbol 값
→ 그대로 Symbol 키

그 외의 값
→ 원시값 변환
→ String 값으로 변환
→ 문자열 키
```

---

### `ToObject`

`ToObject`는 원시값을 대응하는 객체 형태로 다룰 수 있게 만드는 추상 연산이다.

```js
"hello".toUpperCase();
```

String 원시값에서 메서드를 호출할 수 있는 것은 프로퍼티 접근 과정에서 String 값에 대응하는 객체 동작을 사용할 수 있기 때문이다.

```txt
"hello" 원시값
→ String 관련 객체 기능 사용
→ toUpperCase 메서드 탐색
→ 호출
→ "HELLO" 반환
```

`null`과 `undefined`는 객체로 변환할 수 없다.

```js
null.toString(); // TypeError
undefined.toString(); // TypeError
```

---

### 타입 변환과 연산자

같은 값이라도 사용되는 연산자에 따라 다른 타입 변환이 수행될 수 있다.

```js
"5" + 1; // "51"
"5" - 1; // 4
"5" * 2; // 10
```

```txt
"5" + 1
→ 문자열 연결 가능
→ 1을 "1"로 변환
→ "51"

"5" - 1
→ 숫자 뺄셈
→ "5"를 5로 변환
→ 4

"5" * 2
→ 숫자 곱셈
→ "5"를 5로 변환
→ 10
```

타입 변환을 이해할 때는 단순히 “문자열이 숫자로 변한다”라고 외우기보다, 해당 연산자가 어떤 타입을 요구하는지를 함께 봐야 한다.

## 1.2.6 값 전달과 공유 참조

JavaScript에서 할당, 함수 인수 전달, 함수 반환은 모두 값을 전달한다.

```js
const first = 10;
const second = first;
```

`first`의 값을 읽어 `second`에 전달한다.

```txt
first  → Number 값 10
second → Number 값 10
```

객체도 마찬가지로 객체값이 전달된다.

```js
const first = {
  count: 0,
};

const second = first;
```

이 경우 두 바인딩은 같은 객체를 나타내는 값을 공유한다.

```txt
first  ─┐
        ├→ 같은 객체 { count: 0 }
second ─┘
```

이를 이해할 때 다음 두 사실을 함께 봐야 한다.

```txt
JavaScript는 값을 전달한다
객체값을 전달하면 같은 객체가 여러 위치에서 공유될 수 있다
```

---

### 원시값의 할당

```js
let first = 10;
let second = first;

second = 20;
```

결과는 다음과 같다.

```js
console.log(first); // 10
console.log(second); // 20
```

`second`를 변경해도 `first`는 영향을 받지 않는다.

```txt
할당 직후
first  → 10
second → 10

second 재할당 후
first  → 10
second → 20
```

숫자 값 `10`의 내부가 변경된 것이 아니라 `second`가 다른 값과 다시 연결되었다.

---

### 객체값의 할당

```js
const first = {
  count: 0,
};

const second = first;

second.count = 10;
```

```js
console.log(first.count); // 10
console.log(second.count); // 10
```

`first`와 `second`가 같은 객체를 공유하고 있으므로 `second`를 통해 객체를 변경하면 `first`로 읽을 때도 변경된 상태가 보인다.

```txt
first  ─┐
        ├→ 객체 { count: 10 }
second ─┘
```

이는 `first` 객체가 `second` 객체로 복사된 것이 아니다. 두 바인딩이 하나의 객체를 공유하고 있다.

---

### 객체 변경과 바인딩 재할당

객체의 프로퍼티를 변경하는 것과 바인딩을 다른 객체로 재할당하는 것은 다르다.

```js
let first = {
  count: 0,
};

let second = first;
```

프로퍼티를 변경하면 공유 객체가 바뀐다.

```js
second.count = 10;

console.log(first.count); // 10
```

바인딩을 재할당하면 `second`만 다른 객체와 연결된다.

```js
second = {
  count: 20,
};

console.log(first.count); // 10
console.log(second.count); // 20
```

구조는 다음과 같다.

```txt
재할당 전

first  ─┐
        ├→ 객체 A { count: 10 }
second ─┘


재할당 후

first  → 객체 A { count: 10 }
second → 객체 B { count: 20 }
```

객체 A가 객체 B로 변한 것이 아니다. `second`가 객체 B와 새롭게 연결된 것이다.

---

### 함수 인수 전달

함수를 호출할 때도 인수 표현식의 평가 결과인 값이 매개변수에 전달된다.

#### 원시값 전달

```js
function change(value) {
  value = 20;
}

let number = 10;

change(number);

console.log(number); // 10
```

과정은 다음과 같다.

```txt
number의 값 10을 읽음
→ 매개변수 value에 10 전달
→ 함수 안에서 value를 20으로 재할당
→ 바깥 number에는 영향 없음
```

#### 객체값 전달

```js
function change(user) {
  user.name = "Ares";
}

const user = {
  name: "Mars",
};

change(user);

console.log(user.name); // "Ares"
```

함수의 매개변수와 바깥 바인딩이 같은 객체를 공유하므로, 함수 안에서 객체의 프로퍼티를 변경하면 바깥에서도 변경이 보인다.

```txt
바깥 user ─┐
           ├→ 같은 객체
매개변수 user ─┘
```

#### 매개변수 재할당

```js
function replace(user) {
  user = {
    name: "Ares",
  };
}

const user = {
  name: "Mars",
};

replace(user);

console.log(user.name); // "Mars"
```

함수 안에서 매개변수 `user`를 재할당해도 바깥의 `user` 바인딩은 바뀌지 않는다.

```txt
호출 직후

바깥 user ─────┐
               ├→ 객체 A { name: "Mars" }
매개변수 user ─┘


매개변수 재할당 후

바깥 user    → 객체 A { name: "Mars" }
매개변수 user → 객체 B { name: "Ares" }
```

따라서 JavaScript가 객체를 “참조에 의한 전달” 방식으로 전달한다고 표현하면 매개변수 재할당까지 바깥 바인딩에 반영된다고 오해할 수 있다.

보다 정확하게는 다음과 같이 표현할 수 있다.

> JavaScript는 항상 값을 전달하며, 전달된 값이 객체값이면 호출자와 함수가 같은 객체를 공유할 수 있다.

---

### `const`와 객체 변경

`const`는 바인딩의 재할당을 금지한다.

```js
const user = {
  name: "Mars",
};
```

다른 객체를 다시 할당할 수 없다.

```js
user = {
  name: "Ares",
}; // TypeError
```

그러나 현재 연결된 객체의 프로퍼티 변경까지 금지하는 것은 아니다.

```js
user.name = "Ares";

console.log(user.name); // "Ares"
```

```txt
const가 막는 것
user 바인딩을 다른 값과 다시 연결

const가 막지 않는 것
user가 가리키는 객체의 상태 변경
```

객체 자체의 변경을 제한하려면 별도의 방법이 필요하다.

```js
const user = Object.freeze({
  name: "Mars",
});
```

다만 `Object.freeze()`도 기본적으로 해당 객체의 직접 프로퍼티에 적용되는 얕은 동결이다.

### 얕은 복사

객체 스프레드 문법이나 `Object.assign()`으로 새로운 객체를 만들 수 있다.

```js
const original = {
  name: "Mars",
};

const copied = {
  ...original,
};

original === copied; // false
```

`original`과 `copied`는 서로 다른 객체다.

```txt
original → 객체 A
copied   → 객체 B
```

직접 프로퍼티의 값은 복사된다.

```js
copied.name = "Ares";

console.log(original.name); // "Mars"
console.log(copied.name); // "Ares"
```

하지만 중첩 객체의 객체값은 그대로 전달될 수 있다.

```js
const original = {
  profile: {
    name: "Mars",
  },
};

const copied = {
  ...original,
};
```

```js
original.profile === copied.profile; // true
```

```txt
original → 객체 A
           └─ profile ─┐
                       ├→ 객체 C
copied   → 객체 B      │
           └─ profile ─┘
```

따라서 다음 변경은 원본에서도 보인다.

```js
copied.profile.name = "Ares";

console.log(original.profile.name); // "Ares"
```

이처럼 최상위 프로퍼티만 새로운 객체로 복사하는 것을 얕은 복사라고 한다.

---

### 깊은 복사

깊은 복사는 중첩된 객체까지 새로운 객체로 복제하여 원본과 공유되는 객체를 줄이는 방식이다.

```js
const original = {
  profile: {
    name: "Mars",
  },
};

const copied = structuredClone(original);
```

```js
original === copied; // false
original.profile === copied.profile; // false
```

```js
copied.profile.name = "Ares";

console.log(original.profile.name); // "Mars"
```

다만 `structuredClone()`이 모든 JavaScript 값을 복제할 수 있는 것은 아니다. 함수나 일부 특수한 객체는 복제할 수 없으며, 어떤 내부 상태가 어떻게 복제되는지는 구조화 복제 알고리즘의 규칙에 따른다.

“깊은 복사”도 언제나 모든 내부 연결을 완전히 동일하게 새로 만드는 단순한 개념은 아니다. 객체 종류와 프로그램의 목적에 맞는 복사 방식을 선택해야 한다.

### 구조 분해와 값 전달

구조 분해도 객체나 배열의 프로퍼티 값을 읽어 새로운 바인딩에 연결한다.

```js
const user = {
  name: "Mars",
  profile: {
    age: 20,
  },
};

const { name, profile } = user;
```

`name`에는 String 원시값이 전달된다.

```txt
name → "Mars"
```

`profile`에는 객체값이 전달되므로 원래 객체와 같은 중첩 객체를 공유한다.

```js
profile === user.profile; // true
```

```js
profile.age = 30;

console.log(user.profile.age); // 30
```

구조 분해 자체가 중첩 객체를 복사하는 것은 아니다.

## 전체 구조

```txt
값과 타입
│
├─ 값
│  ├─ 표현식을 평가하여 얻는 런타임 데이터
│  └─ 모든 값은 하나의 언어 타입에 속함
│
├─ 원시값
│  ├─ undefined
│  ├─ null
│  ├─ boolean
│  ├─ number
│  ├─ bigint
│  ├─ string
│  └─ symbol
│
├─ 객체값
│  ├─ 프로퍼티를 가질 수 있음
│  ├─ 고유한 정체성을 가짐
│  ├─ 일반적으로 상태를 변경할 수 있음
│  ├─ 배열도 객체
│  └─ 함수도 객체
│
├─ 동일성 비교
│  ├─ ==
│  ├─ ===
│  ├─ Object.is
│  └─ SameValueZero
│
├─ 타입 변환
│  ├─ 명시적 변환
│  ├─ 암시적 변환
│  ├─ ToPrimitive
│  ├─ ToBoolean
│  ├─ ToNumber
│  ├─ ToNumeric
│  ├─ ToString
│  ├─ ToPropertyKey
│  └─ ToObject
│
└─ 값 전달과 공유
   ├─ JavaScript는 값을 전달
   ├─ 원시값 할당
   ├─ 객체값 공유
   ├─ 객체 변경과 재할당의 차이
   ├─ 함수 인수 전달
   ├─ 얕은 복사
   └─ 깊은 복사
```

값과 타입을 이해할 때 가장 중요한 관계는 다음과 같다.

```txt
소스 코드의 표현식
→ 표현식을 평가
→ 값 생성 또는 획득
→ 값의 타입에 따라 연산 수행
→ 필요하면 타입 변환
→ 결과값을 다른 연산이나 바인딩으로 전달
```

그리고 원시값과 객체값의 차이는 다음 문장으로 요약할 수 있다.

```txt
원시값은 값 자체가 불변이고,
객체값은 고유한 정체성을 가지며 여러 바인딩에서 공유될 수 있다.
```
