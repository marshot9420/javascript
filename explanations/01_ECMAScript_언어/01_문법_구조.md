# 1.1. 문법 구조

ECMAScript의 문법 구조는 소스 코드가 어떤 문자와 토큰으로 구성되고, 그 토큰들이 어떤 형태로 결합되어 유효한 JavaScript 코드가 되는지를 정의한다.

가장 기본적인 처리 관계는 다음과 같다.

```txt
소스 텍스트
→ 어휘 문법에 따라 입력 요소와 토큰으로 구분
→ 토큰이 구문 문법에 따라 결합
→ 표현식, 문, 선언 등의 문법 구조 형성
→ 정적 문법 검사
→ 오류가 없으면 평가
```

예를 들어 다음 코드가 있다.

```js
const result = 10 + 20;
```

어휘 문법의 관점에서는 다음과 같은 토큰으로 구분된다.

```txt
const
result
=
10
+
20
;
```

구문 문법의 관점에서는 이 토큰들이 다음과 같은 구조를 형성한다.

```txt
어휘 선언
├─ const
├─ 바인딩 식별자
│  └─ result
├─ =
├─ 초기화 표현식
│  └─ 덧셈 표현식
│     ├─ 숫자 리터럴: 10
│     ├─ +
│     └─ 숫자 리터럴: 20
└─ ;
```

ECMAScript 문법은 단순히 코드의 외형만 정의하지 않는다.

문법 생산식에 따라 소스 코드를 구조화한 뒤, 해당 구조에 정적 의미 규칙과 Early Error 규칙을 적용하여 실제로 허용되는 코드인지 검사한다.

```txt
문법 구조
│
├─ 어휘 문법
│  └─ 문자로부터 입력 요소와 토큰을 구분
│
├─ 구문 문법
│  ├─ 표현식
│  ├─ 문
│  ├─ 선언
│  └─ Script·Module
│
├─ 줄 종결자와 세미콜론
│  ├─ [no LineTerminator here]
│  ├─ 제한 문법
│  └─ 세미콜론 자동 삽입
│
└─ 정적 문법 검사
   ├─ 구문 오류
   ├─ Early Error
   └─ strict mode 문법 제약
```

## 1.1.1 어휘 문법

어휘 문법은 소스 텍스트의 문자들을 구문 문법이 사용할 입력 요소와 토큰으로 구분하는 규칙이다.

```txt
소스 텍스트
├─ 공백
├─ 줄 종결자
├─ 주석
└─ 토큰
```

구문 문법은 일반적으로 공백과 주석을 직접 사용하지 않고, 어휘 문법이 구분한 토큰들을 입력으로 사용한다.

다만 줄 종결자는 토큰이 아니면서도 다음과 같은 문법 판단에 영향을 준다.

```txt
줄 종결자의 영향
├─ 세미콜론 자동 삽입
├─ [no LineTerminator here] 제약
├─ 제한 문법의 해석
└─ 여러 줄 주석 내부의 줄바꿈
```

예를 들어 다음 코드가 있다.

```js
const value = 10;
```

공백을 포함한 소스 텍스트는 다음과 같다.

```txt
const[공백]value[공백]=[공백]10;
```

공백은 토큰 사이를 구분하지만 그 자체가 일반적인 ECMAScript 토큰은 아니다.

구문 문법으로 전달되는 주요 토큰은 다음과 같다.

```txt
const
value
=
10
;
```

#### 공백

공백은 토큰을 분리하기 위해 필요할 수 있다.

```js
constvalue = 10;
```

위 코드의 `constvalue`는 `const`와 `value`가 아니라 하나의 식별자 이름 토큰으로 인식된다.

따라서 다음 코드와는 의미가 다르다.

```js
const value = 10;
```

반면 구두점만으로 토큰의 경계가 명확한 경우 공백은 필요하지 않을 수 있다.

```js
value = 10;
```

#### 줄 종결자

줄 종결자는 다음과 같은 문자를 포함한다.

```txt
Line Feed
Carriage Return
Line Separator
Paragraph Separator
```

줄 종결자는 일반 토큰은 아니지만 코드의 해석을 변경할 수 있다.

```js
return;
value;
```

이 코드는 일반적으로 다음과 같이 해석된다.

```js
return;
value;
```

#### 주석

한 줄 주석은 줄 종결자 전까지 이어진다.

```js
const value = 10; // 한 줄 주석
```

여러 줄 주석은 `/*`와 `*/` 사이에 작성한다.

```js
const value = /* 설명 */ 10;
```

여러 줄 주석 내부에 줄 종결자가 포함된 경우에는 구문 문법상 그 위치에 줄 종결자가 있는 것처럼 영향을 줄 수 있다.

```js
return;
/*
여러 줄 주석
*/ value;
```

이 경우 `return`과 `value` 사이에 줄 종결자가 존재하는 것으로 처리될 수 있다.

### 토큰

토큰은 구문 문법이 하나의 단위로 취급하는 입력 요소다.

```txt
토큰
├─ 식별자 이름
├─ 예약어
├─ 구두점
├─ 리터럴 토큰
└─ 템플릿 관련 토큰
```

토큰은 문자 하나와 같지 않다.

```js
const
```

`const`는 다섯 문자로 구성되지만 하나의 토큰이다.

```js
123.45;
```

`123.45`도 여러 문자로 구성되지만 하나의 `NumericLiteral` 토큰이다.

```js
===
```

`===`도 세 문자가 아니라 하나의 구두점 토큰으로 인식된다.

#### 식별자 이름

식별자 이름은 변수, 함수, 클래스, 프로퍼티 등의 이름을 구성할 수 있는 어휘 문법상의 토큰이다.

어휘 문법에서 직접 정의되는 주요 이름 토큰은 다음과 같다.

```txt
식별자 이름
├─ IdentifierName
└─ PrivateIdentifier
```

##### IdentifierName

`IdentifierName`은 식별자 형태를 가진 가장 넓은 어휘 문법상의 이름이다.

```js
value
userName
calculateTotal
class
return
await
```

`class`, `return`과 같은 예약어도 문자 형태 자체는 `IdentifierName`에 해당한다.

다만 `IdentifierName`이라는 사실만으로 모든 문법 위치에서 일반 식별자로 사용할 수 있는 것은 아니다.

```js
const class = 10; // SyntaxError
```

`class`는 `IdentifierName` 형태이지만 예약어이므로 바인딩 식별자로 사용할 수 없다.

관계는 대략 다음과 같다.

```txt
IdentifierName
├─ 일반 식별자로 사용할 수 있는 이름
├─ 예약어
└─ 문맥에 따라 허용 여부가 달라지는 이름
```

`await`와 `yield`는 코드가 모듈인지, async 함수 내부인지, 제너레이터 함수 내부인지 등에 따라 허용 여부가 달라진다.

##### PrivateIdentifier

`PrivateIdentifier`는 클래스의 private 요소를 나타내는 별도의 어휘 토큰이다.

```js
class Counter {
  #count = 0;

  increment() {
    this.#count++;
  }
}
```

여기서 `#count`는 일반 식별자나 문자열 프로퍼티 키가 아니다.

```txt
PrivateIdentifier
├─ #
└─ IdentifierName
```

private 이름은 해당 클래스의 private 환경에서 별도로 관리되며, 일반적인 문자열 프로퍼티 키와도 구별된다.

```js
class Example {
  #value = 10;
}

const example = new Example();

example["#value"]; // private 필드에 접근하지 않음
```

##### 구문 문법에서의 식별자 역할

`IdentifierName`은 어휘 문법상의 토큰 형태다.

이 토큰은 구문 문법에서 놓인 위치에 따라 서로 다른 역할을 맡는다.

```txt
IdentifierName 토큰
├─ IdentifierReference
├─ BindingIdentifier
└─ LabelIdentifier
```

예를 들어 다음 코드에서 동일한 형태의 이름도 서로 다른 문법 역할을 가진다.

```js
const count = 10;

console.log(count);

outer: while (true) {
  break outer;
}
```

```txt
첫 번째 count    BindingIdentifier
두 번째 count    IdentifierReference
outer:            LabelIdentifier
break outer       LabelIdentifier
```

`IdentifierReference`, `BindingIdentifier`, `LabelIdentifier`는 어휘 토큰의 종류가 아니라 구문 문법에서 식별자 이름이 사용되는 역할이다.

#### 예약어

예약어는 일반적인 식별자로 사용할 수 없도록 예약된 단어다.

예약어에는 문법에서 직접 기능을 수행하는 키워드뿐 아니라 미래 확장을 위해 예약된 이름과 일부 리터럴 단어가 포함된다.

```txt
예약어
├─ 키워드
├─ 미래 예약어
├─ null
├─ true
└─ false
```

대표적인 키워드는 다음과 같다.

```txt
break
case
catch
class
const
continue
debugger
default
delete
do
else
export
extends
finally
for
function
if
import
in
instanceof
new
return
super
switch
this
throw
try
typeof
var
void
while
with
yield
```

키워드는 특정 문법 구조를 구성한다.

```js
if (condition) {
  return value;
}
```

여기서 다음 단어들은 각각 문법적인 역할을 가진다.

```txt
if       조건문 시작
return   함수 반환문 시작
```

##### 키워드와 예약어의 차이

키워드와 예약어는 완전히 같은 개념이 아니다.

```txt
키워드
문법에서 직접 특별한 기능을 수행하는 단어

예약어
일반적인 식별자로 사용할 수 없도록 예약된 단어
```

많은 키워드는 예약어이지만, 특정 문법 위치에서만 특별한 의미를 가지는 이름도 있다.

예를 들어 `async`는 항상 예약어가 아니다.

```js
const async = 10;
```

그러나 다음 위치에서는 비동기 함수 문법을 구성한다.

```js
async function load() {}
```

##### 문맥적 키워드

문맥적 키워드는 특정 문법 위치에서만 특별한 의미를 가진다.

```js
for (const item of items) {
}
```

여기서 `of`는 `for-of`문을 구성한다.

```js
import { value as renamed } from "./module.js";
```

여기서 `as`와 `from`은 모듈 구문 안에서 특별한 역할을 한다.

```js
class Example {
  static create() {}

  get value() {
    return 10;
  }

  set value(nextValue) {}
}
```

여기서 `static`, `get`, `set`도 해당 문법 위치에서만 특별한 의미를 가진다.

따라서 문맥적 키워드를 언제나 사용할 수 없는 예약어로 생각하면 안 된다.

구두점은 사용되는 문법 위치에 따라 서로 다른 역할을 맡는다.

```js
const result = left + right;
```

```txt

+    덧셈 표현식을 구성하는 구두점
;    선언의 끝을 구성하는 구두점
```

같은 구두점도 문맥에 따라 역할이 달라질 수 있다.

```js
const object = { name: "Mars" };
const result = condition ? first : second;
```

첫 번째 `:`는 객체 프로퍼티 정의를 구성하고, 두 번째 `:`는 조건 표현식을 구성한다.

##### 나눗셈 구두점

`/`와 `/=`는 정규 표현식 리터럴의 시작과 구별해야 하므로 일반적인 구두점과 별도의 어휘 목표 문맥에서 처리된다.

```js
left / right;
value /= 2;
```

---

#### 리터럴 토큰

리터럴은 값을 소스 코드에 직접 나타내는 문법적 표기다.

어휘 문법에서 하나의 토큰으로 인식되는 주요 리터럴은 다음과 같다.

```txt
리터럴 토큰
├─ NullLiteral
├─ BooleanLiteral
├─ NumericLiteral
├─ StringLiteral
└─ RegularExpressionLiteral
```

리터럴은 소스 코드의 문법적 표기이며, 값은 해당 리터럴을 평가하여 얻는 런타임 데이터다.

```txt
소스 코드의 10    NumericLiteral
평가 결과         Number 값 10
```

다음 두 표현식은 모두 Number 값 `10`을 만들지만 문법 구조는 다르다.

```js
10;
```

`10`은 숫자 리터럴이다.

```js
5 + 5;
```

`5 + 5` 전체는 덧셈 표현식이며 리터럴이 아니다.

##### NullLiteral

```js
null;
```

`null` 값을 직접 나타낸다.

`null`은 리터럴이지만 `undefined`는 리터럴이 아니다.

```js
undefined;
```

`undefined`는 `undefined`라는 이름을 참조하는 `IdentifierReference`다.

##### BooleanLiteral

```js
true;
false;
```

각각 Boolean 값 `true`와 `false`를 나타낸다.

##### NumericLiteral

`NumericLiteral`은 Number 또는 BigInt 값을 나타내는 숫자 표기를 포함한다.

```js
10;
3.14;
1e3;
0b1010;
0o12;
0xff;
10n;
0xffn;
```

숫자 구분자 `_`를 사용할 수도 있다.

```js
1_000_000;
```

###### Number 리터럴

```js
10;
3.14;
1e3;
0b1010;
0o12;
0xff;
```

Number 타입의 값을 나타낸다.

###### BigInt 리터럴

```js
10n;
0xffn;
```

끝의 `n`은 해당 숫자 표기가 Number가 아니라 BigInt 값을 나타낸다는 뜻이다.

##### StringLiteral

```js
"hello";
"hello";
```

큰따옴표나 작은따옴표를 사용하여 문자열 값을 나타낸다.

```js
"line\nbreak";
```

이스케이프 시퀀스를 사용하여 소스에 직접 적기 어려운 문자를 표현할 수 있다.

##### RegularExpressionLiteral

```js
/hello/gi;
```

정규 표현식의 패턴과 플래그를 소스 코드에 직접 나타낸다.

정규 표현식 리터럴은 어휘 문법에서 하나의 특별한 토큰으로 인식된다.

```txt
/hello/gi
└─ 하나의 RegularExpressionLiteral 토큰
```

구문 문법에서는 이 토큰이 기본 표현식의 한 형태로 사용된다.

---

#### 템플릿 관련 토큰

템플릿 리터럴은 일반적인 문자열 리터럴과 달리 내부에 표현식을 포함할 수 있다.

```js
`hello`;
```

```js
`Hello, ${name}`;
```

표현식이 없는 템플릿은 하나의 템플릿 관련 어휘 요소로 처리될 수 있다.

표현식을 포함한 템플릿은 여러 어휘 요소와 표현식으로 나뉜다.

```txt
`Hello, ${name}!`
│        │    │
│        │    └─ TemplateTail
│        └────── IdentifierReference
└─────────────── TemplateHead
```

대표적인 템플릿 관련 어휘 요소는 다음과 같다.

```txt
템플릿 관련 토큰
├─ NoSubstitutionTemplate
├─ TemplateHead
├─ TemplateMiddle
└─ TemplateTail
```

예를 들어 다음 템플릿이 있다.

```js
`A ${first} B ${second} C`;
```

대략 다음 요소로 구분된다.

```txt
TemplateHead
first 표현식
TemplateMiddle
second 표현식
TemplateTail
```

템플릿 리터럴 전체는 하나의 문자열 리터럴 토큰이 아니라 여러 템플릿 관련 토큰과 구문 표현식이 결합된 구조다.

---

### 최장 일치

어휘 분석에서는 현재 위치에서 만들 수 있는 토큰 중 가능한 한 긴 토큰을 선택한다.

이를 최장 일치 또는 최대 일치 원칙으로 이해할 수 있다.

```js
value === other;
```

`===`는 다음처럼 구분되지 않는다.

```txt
==
=
```

가능한 더 긴 토큰인 `===` 하나로 인식된다.

```js
count++;
```

`++`도 두 개의 `+` 토큰으로 나뉘지 않고 하나의 증가 연산자용 구두점 토큰으로 인식된다.

```js
value >>>= 1;
```

`>>>=` 역시 가능한 한 긴 하나의 구두점 토큰으로 인식된다.

최장 일치는 단순히 문자 수만 보는 규칙은 아니다. 현재 적용되는 어휘 목표와 해당 위치에서 허용되는 토큰 종류 안에서 가장 긴 토큰을 선택한다.

---

### 어휘 목표 기호

일부 문자는 소스 텍스트만 독립적으로 보고 항상 같은 방식으로 토큰화할 수 없다.

대표적인 예가 `/`다.

```js
left / right;
```

여기서 `/`는 나눗셈 구두점이다.

```js
const pattern = /hello/g;
```

여기서 `/hello/g`는 하나의 정규 표현식 리터럴이다.

JavaScript 파서는 현재 구문 위치에서 어떤 종류의 토큰이 가능한지를 이용해 적절한 어휘 목표 기호를 선택한다.

대표적인 어휘 목표 기호는 다음과 같다.

```txt
InputElementDiv
InputElementRegExp
InputElementRegExpOrTemplateTail
InputElementTemplateTail
```

개념적으로는 다음 문맥으로 이해할 수 있다.

<table>
  <thead>
    <tr>
      <th>문맥</th>
      <th>설명</th>
      <th>예시</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>나눗셈 문맥</td>
      <td><code>/</code>와 <code>/=</code>를 구두점으로 인식할 수 있다.</td>
      <td><code>left / right</code></td>
    </tr>
    <tr>
      <td>정규 표현식 문맥</td>
      <td><code>/</code>로 시작하는 정규 표현식 리터럴을 인식할 수 있다.</td>
      <td><code>/hello/g</code></td>
    </tr>
    <tr>
      <td>템플릿 문맥</td>
      <td>템플릿 표현식 뒤의 템플릿 중간·끝 부분을 인식할 수 있다.</td>
      <td><code>`A ${value} B`</code></td>
    </tr>
  </tbody>
</table>

따라서 JavaScript의 토큰화는 소스 텍스트를 처음부터 끝까지 완전히 독립적으로 잘라내는 단순 작업이 아니다.

```txt
현재 구문 문맥
→ 적용할 어휘 목표 기호 선택
→ 현재 위치에서 가능한 토큰 인식
→ 구문 분석 계속
```

## 1.1.2 구문 문법

구문 문법은 어휘 문법이 만든 토큰들이 어떤 순서와 구조로 결합되어 유효한 JavaScript 코드가 되는지를 정의한다.

```txt
어휘 문법
└─ 토큰 생성

구문 문법
└─ 토큰을 문법 생산식에 따라 결합
```

예를 들어 다음 토큰이 있다.

```txt
const
result
=
10
+
20
;
```

구문 문법은 이 토큰들을 다음과 같은 구조로 분석한다.

```txt
LexicalDeclaration
├─ const
├─ BindingIdentifier: result
├─ =
├─ AdditiveExpression
│  ├─ NumericLiteral: 10
│  ├─ +
│  └─ NumericLiteral: 20
└─ ;
```

구문 문법의 주요 구조는 다음과 같다.

```txt
구문 문법
├─ 표현식
├─ 문
├─ 선언
└─ 최상위 구문 목표
   ├─ Script
   └─ Module
```

---

### 표현식

표현식은 평가되는 코드 구조다.

일반적으로는 값을 만들어 내는 코드라고 설명할 수 있지만, 명세상 표현식의 직접적인 평가 결과가 항상 곧바로 ECMAScript 값인 것은 아니다.

식별자 참조나 프로퍼티 접근 표현식은 먼저 `Reference` 타입의 명세 레코드를 만들 수 있다.

```txt
표현식 평가
├─ ECMAScript 값
├─ Reference
├─ 함수·클래스 객체
└─ 평가 도중 발생한 abrupt completion
```

예를 들어 다음은 모두 표현식이다.

```js
10;
```

숫자 리터럴 표현식이다.

```js
first + second;
```

덧셈 표현식이다.

```js
user.name;
```

프로퍼티 접근 표현식이다.

```js
calculate();
```

호출 표현식이다.

```js
result = 10;
```

할당 표현식이다.

#### 표현식의 재귀적 구조

표현식은 다른 표현식을 포함하여 더 큰 표현식을 만든다.

```js
calculate(price * quantity + shippingFee);
```

구조는 다음과 같다.

```txt
호출 표현식
├─ 호출 대상 표현식
│  └─ IdentifierReference: calculate
└─ 인수 표현식
   └─ 덧셈 표현식
      ├─ 곱셈 표현식
      │  ├─ IdentifierReference: price
      │  └─ IdentifierReference: quantity
      └─ IdentifierReference: shippingFee
```

---

#### 기본 표현식

기본 표현식은 표현식 문법의 기초가 되는 형태다.

```txt
기본 표현식
├─ this
├─ IdentifierReference
├─ 리터럴
├─ 배열 리터럴
├─ 객체 리터럴
├─ 함수 표현식
├─ 클래스 표현식
├─ 정규 표현식 리터럴
├─ 템플릿 리터럴
└─ 괄호로 묶인 표현식
```

##### this

```js
this;
```

현재 실행 문맥에서 결정되는 `this` 값을 나타내는 표현식이다.

`this`의 실제 결정 방식은 함수 호출 방식과 실행 문맥에서 다룬다.

##### IdentifierReference

기존 바인딩을 이름으로 참조하는 구문이다.

```js
const count = 10;

console.log(count);
```

두 번째 `count`는 `IdentifierReference`다.

평가는 대략 다음 과정으로 이어진다.

```txt
이름 확인
→ 현재 환경에서 바인딩 탐색
→ Reference 생성
→ 필요한 위치에서 GetValue
→ 바인딩에 연결된 값 획득
```

##### 리터럴

구문 문법의 좁은 `Literal` 범주는 다음을 포함한다.

```txt
Literal
├─ NullLiteral
├─ BooleanLiteral
├─ NumericLiteral
└─ StringLiteral
```

이 토큰들은 기본 표현식 위치에서 평가되어 각 리터럴에 해당하는 값을 만든다.

##### 배열 리터럴

```js
[1, 2, 3];
```

배열 리터럴은 하나의 어휘 토큰이 아니다.

```txt
[
1
,
2
,
3
]
```

여러 토큰이 구문 문법에 따라 결합된 `ArrayLiteral` 표현식이다.

##### 객체 리터럴

```js
({
  name: "Mars",
  age: 10,
});
```

객체 리터럴도 여러 토큰이 결합된 표현식이다.

```txt
{
name
:
"Mars"
,
age
:
10
}
```

##### 함수 표현식

```js
const run = function () {};
const generate = function* () {};
const load = async function () {};
const stream = async function* () {};
```

오른쪽의 함수 구문들은 함수 객체를 만드는 표현식이다.

##### 클래스 표현식

```js
const Product = class {};
```

오른쪽의 `class {}`는 클래스 객체를 만드는 표현식이다.

##### 정규 표현식 리터럴

```js
/hello/gi;
```

어휘 문법에서 하나의 `RegularExpressionLiteral` 토큰으로 인식되고, 구문 문법에서는 기본 표현식으로 사용된다.

##### 템플릿 리터럴

```js
`hello`;
```

```js
`Hello, ${name}`;
```

템플릿 관련 토큰과 내부 표현식이 결합된 구문 구조다.

##### 괄호로 묶인 표현식

```js
1 + 2;
```

괄호는 내부 표현식을 하나의 묶음으로 해석하게 한다.

괄호 자체가 별도의 런타임 값을 만드는 것은 아니며, 표현식의 결합 구조와 문법 해석에 영향을 준다.

---

#### 왼쪽 값 표현식

왼쪽 값 표현식은 프로퍼티 접근, 함수 호출, 생성자 호출 등 표현식 계층의 왼쪽 부분을 구성하는 구문이다.

```txt
왼쪽 값 표현식
├─ 프로퍼티 접근
├─ optional chaining
├─ 함수 호출
├─ 메서드 호출
├─ 생성자 호출
└─ tagged template
```

명칭에 왼쪽 값이라는 표현이 들어가지만, 이 범주에 속한 모든 표현식이 유효한 할당 대상인 것은 아니다.

```js
run() = 10; // SyntaxError
```

함수 호출은 왼쪽 값 표현식 계층에 포함되지만 할당 대상이 될 수 없다.

##### 프로퍼티 접근

```js
user.name;
user["name"];
```

객체의 프로퍼티에 대한 `Reference`를 만든다.

```txt
user.name
├─ 기준 객체 표현식: user
└─ 프로퍼티 키: "name"
```

`user.name`의 `name`은 현재 환경에서 `name` 바인딩을 찾지 않는다.

```js
const name = "outside";

const user = {
  name: "Mars",
};

console.log(user.name);
```

```txt
첫 번째 name      변수 바인딩
객체의 name       프로퍼티 이름
user.name의 name  정적으로 지정된 프로퍼티 키
```

예약어도 프로퍼티 이름으로 사용할 수 있다.

```js
const object = {
  class: "A",
  return: "B",
};

console.log(object.class);
console.log(object.return);
```

##### optional chaining

```js
user?.name;
user?.getName?.();
```

중간 값이 `null` 또는 `undefined`이면 이후 프로퍼티 접근이나 호출을 수행하지 않고 `undefined`를 결과로 만든다.

##### 함수 호출

```js
calculate();
```

호출 대상 표현식과 인수 표현식들로 구성된다.

```txt
호출 표현식
├─ 호출 대상 표현식
└─ 인수 목록
```

##### 메서드 호출

```js
user.getName();
```

프로퍼티 접근으로 얻은 함수 값을 해당 객체와 연결된 호출 형태로 실행한다.

##### 생성자 호출

```js
new User();
```

생성자 호출을 수행하여 새로운 객체를 만들 수 있다.

##### tagged template

```js
tag`Hello, ${name}`;
```

템플릿 리터럴을 함수 호출과 유사한 방식으로 처리한다.

---

#### 연산 표현식

연산 표현식은 하나 이상의 피연산자에 연산을 적용하는 표현식이다.

```txt
연산 표현식
├─ 갱신 표현식
├─ 단항 표현식
├─ 산술 표현식
├─ 비트 표현식
├─ 관계 표현식
├─ 동등성 표현식
├─ 논리 표현식
├─ 조건 표현식
├─ 할당 표현식
└─ 쉼표 표현식
```

##### 갱신 표현식

```js
count++;
count--;
++count;
--count;
```

갱신 표현식은 피연산자의 값을 변경하고 표현식 결과를 만든다.

전위와 후위는 표현식 결과가 다르다.

```js
let count = 1;

const first = count++;
// first: 1
// count: 2

const second = ++count;
// second: 3
// count: 3
```

##### 단항 표현식

단항 표현식은 하나의 피연산자에 연산을 적용한다.

```js
!value;
+value;
-value;
typeof value;
void value;
delete object.key;
```

##### 산술 표현식

```js
left ** right;
left * right;
left / right;
left % right;
left + right;
left - right;
```

##### 비트 표현식

```js
value << 1;
value >> 1;
value >>> 1;

left & right;
left ^ right;
left | right;
```

##### 관계 표현식

```js
left < right;
left <= right;
left > right;
left >= right;

key in object;
value instanceof Constructor;
```

##### 동등성 표현식

```js
left == right;
left != right;
left === right;
left !== right;
```

##### 논리 표현식

```js
left && right;
left || right;
left ?? right;
```

논리 표현식은 항상 양쪽 피연산자를 모두 평가하지 않는다.

```js
false && run();
true || run();
value ?? fallback;
```

왼쪽 피연산자의 결과에 따라 오른쪽 표현식의 평가 여부가 결정된다.

```txt
&&
왼쪽이 falsy이면 오른쪽을 평가하지 않음

||
왼쪽이 truthy이면 오른쪽을 평가하지 않음

??
왼쪽이 null 또는 undefined가 아니면 오른쪽을 평가하지 않음
```

##### 조건 표현식

```js
condition ? whenTrue : whenFalse;
```

조건 표현식은 조건의 결과에 따라 두 표현식 중 하나를 평가한다.

```js
const message = isLoggedIn ? "Welcome" : "Login required";
```

JavaScript에서 `if`는 문이지만 삼항 조건 연산자는 표현식이다.

##### 할당 표현식

```js
value = 10;
value += 10;
value ??= fallback;
object.key = "next";
```

할당은 문이 아니라 표현식이다.

```js
const result = (value = 10);
```

할당 표현식도 평가 결과를 가지므로 다른 표현식 안에 들어갈 수 있다.

할당 연산자의 왼쪽은 유효한 할당 대상이어야 한다.

```js
10 = value; // SyntaxError
```

```js
left + right = value; // SyntaxError
```

##### 쉼표 표현식

```js
const result = (first(), second(), third());
```

왼쪽부터 각 표현식을 평가하고 마지막 표현식의 값을 결과로 만든다.

모든 쉼표가 쉼표 연산자인 것은 아니다.

```js
const first = 1,
  second = 2;
```

이 쉼표는 선언 항목을 구분한다.

```js
run(first, second);
```

이 쉼표는 인수를 구분한다.

```js
const result = (first, second);
```

이 쉼표는 쉼표 연산자다.

---

#### 화살표 함수 표현식

```js
const double = (value) => value * 2;
```

화살표 함수는 별도의 선언 형태가 없으며 항상 표현식이다.

본문은 하나의 표현식이나 블록으로 구성할 수 있다.

```js
const double = (value) => value * 2;
```

```js
const double = (value) => {
  return value * 2;
};
```

매개변수와 `=>` 사이에는 줄 종결자가 올 수 없다.

```js
const double = (value)
=> value * 2; // SyntaxError
```

---

#### await 표현식

```js
const result = await promise;
```

`await promise`는 await 표현식이다.

일반적으로 async 함수나 top-level await가 허용되는 Module 문맥에서 사용된다.

`await`의 실행 의미는 비동기 언어 모델에서 다룬다.

---

#### yield 표현식

```js
function* generate() {
  const input = yield 10;
}
```

`yield 10`은 제너레이터 함수 안에서 사용하는 표현식이다.

제너레이터 실행을 중단하고 값을 외부에 전달하며, 이후 다시 실행될 때 값을 전달받을 수 있다.

`yield`의 실행 의미는 함수와 제어에서 다룬다.

#### 연산자 우선순위와 결합 방향

연산자 우선순위는 여러 연산자가 하나의 표현식에 함께 나타날 때 어떤 연산이 더 강하게 묶이는지를 결정한다.

```js
1 + 2 * 3;
```

곱셈이 덧셈보다 우선하므로 다음과 같이 해석된다.

```js
1 + 2 * 3;
```

다음처럼 해석되지 않는다.

```js
(1 + 2) * 3;
```

ECMAScript 명세는 연산자마다 숫자 우선순위를 직접 부여하기보다 표현식 문법을 여러 단계로 계층화한다.

```txt
MultiplicativeExpression
→ AdditiveExpression
→ ShiftExpression
→ RelationalExpression
→ EqualityExpression
→ ...
```

더 강하게 결합하는 표현식 생산식이 더 약하게 결합하는 표현식 생산식 안에 포함된다.

높은 쪽에서 낮은 쪽으로 단순화하면 다음과 같다.

```txt
그룹화                     (...)
멤버 접근·호출             object.key, object[key], call()
new
후위 갱신                  value++, value--
전위·단항                  ++value, !value, typeof value
지수                        **
곱셈                       *, /, %
덧셈                       +, -
비트 이동                  <<, >>, >>>
관계                       <, <=, >, >=, in, instanceof
동등성                     ==, !=, ===, !==
비트 AND                   &
비트 XOR                   ^
비트 OR                    |
논리 AND                   &&
논리 OR                    ||
Null 병합                  ??
조건                       ? :
할당                       =, +=, &&=, ??= 등
yield
쉼표                       ,
```

##### 결합 방향

결합 방향은 같은 우선순위의 연산자가 연속될 때 어느 방향으로 묶이는지를 결정한다.

대부분의 산술 이항 연산자는 왼쪽 결합이다.

```js
a - b - c;
```

```js
a - b - c;
```

지수 연산자는 오른쪽 결합이다.

```js
a ** (b ** c);
```

```js
a ** (b ** c);
```

할당 연산자도 오른쪽 결합이다.

```js
a = b = 10;
```

```js
a = b = 10;
```

##### 우선순위와 평가 순서

우선순위와 피연산자 평가 순서는 서로 다른 개념이다.

```js
left() + middle() * right();
```

문법 구조는 다음과 같다.

```js
left() + middle() * right();
```

그러나 피연산자 표현식은 소스 텍스트의 왼쪽에서 오른쪽 순서로 평가된다.

```txt
left()
→ middle()
→ right()
→ 곱셈
→ 덧셈
```

```txt
우선순위
구문 트리의 결합 구조를 결정

평가 순서
각 하위 표현식을 실제로 처리하는 순서를 결정
```

##### 괄호

괄호를 사용하면 기본 우선순위와 다른 결합 구조를 명시할 수 있다.

```js
(1 + 2) * 3;
```

##### 함께 사용할 수 없는 조합

우선순위만으로 모든 조합이 허용되는 것은 아니다.

```js
a ?? b || c; // SyntaxError
```

Null 병합 연산자와 논리 AND·OR 연산자는 괄호 없이 직접 혼합할 수 없다.

```js
(a ?? b) || c;
a ?? (b || c);
```

지수 연산자의 왼쪽에 일부 단항 표현식을 그대로 사용할 수 없는 등 별도의 구문 제약도 존재한다.

#### 표현식과 값의 차이

```js
1 + 2;
```

```txt
1 + 2    표현식
3        표현식을 평가한 결과인 값
```

표현식은 소스 코드의 문법 구조이고, 값은 실행 중 존재하는 데이터다.

---

#### 표현식과 문의 차이

```js
run();
```

`run()`은 호출 표현식이다.

전체 `run();`은 호출 표현식을 문으로 사용한 표현식 문이다.

```txt
run()     호출 표현식
run();    표현식 문
```

표현식은 다른 표현식 내부에 들어갈 수 있다.

```js
const result = run();
```

일반적인 문은 값이 필요한 위치에 들어갈 수 없다.

```js
const result = if (condition) {
  run();
}; // SyntaxError
```

### 문

문은 프로그램의 제어 흐름과 실행 동작을 구성하는 문법 단위다.

```txt
문
├─ 블록문
├─ 빈 문
├─ 표현식 문
├─ 변수문
├─ 조건문
├─ 반복문
├─ continue문
├─ break문
├─ return문
├─ throw문
├─ try문
├─ 레이블문
├─ with문
└─ debugger문
```

---

#### 블록문

```js
{
  const value = 10;
  console.log(value);
}
```

블록문은 중괄호 안에 여러 문과 선언을 묶는다.

블록문은 하나의 문이므로 문이 들어갈 수 있는 위치에 사용할 수 있다.

```js
if (condition) {
  run();
}
```

`if`문의 본문은 하나의 블록문이다.

블록 내부에는 문뿐 아니라 선언도 포함될 수 있다.

```js
{
  run();
  const value = 10;
  function calculate() {}
}
```

```txt
StatementList
├─ 표현식 문
├─ 어휘 선언
└─ 함수 선언
```

---

#### 빈 문

빈 문은 세미콜론 하나로 구성되며 아무 동작도 하지 않는다.

```js

```

명세상 평가 결과는 `empty`다.

빈 문은 의도하지 않게 작성하면 실행 구조를 바꿀 수 있다.

```js
if (condition);
{
  run();
}
```

실제 구조는 다음과 같다.

```txt
if 문
└─ 본문: 빈 문 ;

별도의 블록문
└─ run();
```

따라서 `run()`은 조건과 관계없이 실행된다.

---

#### 표현식 문

표현식 문은 표현식을 독립적인 문으로 사용한 것이다.

```js
run();
value = 10;
count++;
```

```txt
ExpressionStatement
├─ Expression
└─ ;
```

표현식 문을 평가하면 내부 표현식을 평가하고, 필요한 경우 `GetValue`를 적용한다.

모든 표현식이 아무 수정 없이 표현식 문으로 사용될 수 있는 것은 아니다.

```js
{
  name: "Mars";
}
```

문 시작 위치의 `{`는 객체 리터럴보다 블록으로 해석된다.

객체 리터럴 표현식을 독립적으로 사용하려면 괄호로 묶을 수 있다.

```js
({ name: "Mars" });
```

익명 함수 표현식도 그대로 문 시작 위치에 둘 수 없다.

```js
function () {} // SyntaxError
```

괄호로 묶으면 함수 표현식으로 해석된다.

```js
(function () {});
```

표현식 문은 블록, 함수 선언, 클래스 선언 등과의 모호성을 피하기 위해 특정 토큰으로 시작할 수 없도록 제한된다.

---

#### 변수문

```js
var value = 10;
```

`var` 선언은 새로운 변수 바인딩을 만들지만 명세상 `Declaration`이 아니라 `VariableStatement`라는 문의 한 종류다.

```txt
var 선언        Statement
let·const 선언  Declaration
```

---

#### 조건문

##### if문

```js
if (condition) {
  run();
} else {
  stop();
}
```

구조는 다음과 같다.

```txt
if 문
├─ 조건 표현식
├─ 참일 때 실행할 문
└─ 거짓일 때 실행할 문
```

`if`문 전체는 표현식이 아니지만 내부 조건은 표현식이다.

##### switch문

```js
switch (status) {
  case "READY":
    start();
    break;

  default:
    stop();
}
```

입력 표현식을 평가한 뒤 일치하는 `case`부터 문 목록을 실행한다.

---

#### 반복문

##### while문

```js
while (condition) {
  run();
}
```

조건이 참인 동안 본문을 반복한다.

##### do-while문

```js
do {
  run();
} while (condition);
```

본문을 먼저 실행한 뒤 조건을 검사한다.

##### for문

```js
for (let index = 0; index < 10; index++) {
  run(index);
}
```

초기화, 조건, 갱신 영역으로 구성된다.

##### for-in문

```js
for (const key in object) {
  console.log(key);
}
```

객체의 열거 가능한 프로퍼티 키를 순회한다.

##### for-of문

```js
for (const value of iterable) {
  console.log(value);
}
```

반복 가능한 객체가 제공하는 값을 순회한다.

반복문 전체는 문이지만 내부에는 표현식이나 선언이 포함될 수 있다.

---

#### continue문

```js
continue;
```

현재 반복의 나머지를 중단하고 다음 반복으로 이동한다.

```js
continue outer;
```

레이블이 연결된 반복문의 다음 반복으로 이동할 수도 있다.

---

#### break문

```js
break;
```

현재 반복문이나 `switch`문을 종료한다.

```js
break outer;
```

레이블로 지정된 문을 종료할 수도 있다.

---

#### return문

```js
return;
```

```js
return result;
```

현재 함수 실행을 종료하고 선택적으로 값을 반환한다.

```txt
return 문
└─ 반환 표현식: result
```

`return result;` 전체는 문이고, `result`는 반환값을 계산하는 표현식이다.

---

#### throw문

```js
throw error;
```

현재 실행 흐름을 비정상적으로 종료하고 예외 값을 던진다.

`throw error;` 전체는 문이고, `error`는 던질 값을 계산하는 표현식이다.

`throw`와 표현식 사이에는 줄 종결자가 올 수 없다.

```js
throw
new Error(); // SyntaxError
```

---

#### try문

```js
try {
  run();
} catch (error) {
  handle(error);
} finally {
  cleanup();
}
```

다음 요소로 구성된다.

```txt
try 문
├─ 예외가 발생할 수 있는 블록
├─ catch 절
└─ finally 절
```

`catch`나 `finally` 중 적어도 하나가 필요하다.

---

#### 레이블문

```js
target: {
  break target;
}
```

문에 이름을 붙여 `break`나 `continue`의 대상으로 사용할 수 있게 한다.

레이블 이름은 `LabelIdentifier`로 해석된다.

```js
outer: for (;;) {
  break outer;
}
```

첫 번째 `outer`는 레이블을 정의하고, 두 번째 `outer`는 해당 레이블을 참조한다.

---

#### with문

```js
with (object) {
  console.log(name);
}
```

객체의 프로퍼티를 식별자 탐색 환경에 포함시키는 문이다.

정적 분석과 최적화를 어렵게 만들기 때문에 strict mode에서는 Early Error다.

---

#### debugger문

```js
debugger;
```

디버거가 연결되어 있을 때 실행을 중단할 수 있는 위치를 나타낸다.

---

#### 표현식 문과 표현식이 아닌 문

```txt
표현식 문
표현식을 독립적인 문으로 사용한 것

표현식이 아닌 문
if, while, return, throw, try 등 자체 문법 구조를 가진 문
```

```js
run();
```

표현식 문이다.

```js
if (condition) {
  run();
}
```

전체는 `if`문이다.

그러나 내부에는 표현식과 표현식 문이 들어 있다.

```txt
if 문
├─ condition    IdentifierReference 표현식
└─ 블록문
   └─ run();    표현식 문
```

표현식이 아닌 문이라는 것은 내부에 표현식이 없다는 뜻이 아니다.

문 전체가 값이 필요한 표현식 위치에 들어갈 수 없다는 뜻이다.

---

### 선언

선언은 이름을 도입하고, 그 이름에 연결될 바인딩이나 문법적 정의를 구성한다.

```txt
선언
├─ 어휘 선언
├─ 함수 선언
├─ 제너레이터 함수 선언
├─ async 함수 선언
├─ async 제너레이터 선언
└─ 클래스 선언
```

---

#### 문과 선언의 관계

일상적으로는 `var 선언문`, `let 선언문`, `함수 선언문`처럼 모두 선언문이라고 부르기도 한다.

그러나 ECMAScript 구문 문법에서는 `Statement`와 `Declaration`을 구분한다.

```txt
StatementListItem
├─ Statement
└─ Declaration
```

블록 안에는 문과 선언이 함께 들어갈 수 있지만 문법 범주는 서로 다르다.

```js
{
  run();
  const value = 10;
  function calculate() {}
}
```

```txt
StatementList
├─ 표현식 문
├─ 어휘 선언
└─ 함수 선언
```

---

#### 어휘 선언

어휘 선언에는 `let`과 `const`가 있다.

```txt
LexicalDeclaration
├─ let
└─ const
```

##### let 선언

```js
let value;
let count = 10;
```

변경 가능한 어휘 바인딩을 선언한다.

초기화 표현식은 생략할 수 있다.

```js
let value;
```

해당 선언이 실행될 때 `value`는 `undefined`로 초기화된다.

##### const 선언

```js
const value = 10;
```

다시 할당할 수 없는 어휘 바인딩을 선언한다.

일반적인 `const` 선언에는 초기화 표현식이 필요하다.

```js
const value; // Early Error
```

---

#### 함수 선언

```js
function calculate() {
  return 10;
}
```

함수 이름에 대한 바인딩과 함수 정의를 함께 도입한다.

함수 이름은 `BindingIdentifier`로 사용된다.

---

#### 제너레이터 함수 선언

```js
function* generate() {
  yield 10;
}
```

`yield`를 사용할 수 있는 제너레이터 함수를 선언한다.

---

#### async 함수 선언

```js
async function load() {
  return await request();
}
```

`await`를 사용할 수 있는 async 함수를 선언한다.

---

#### async 제너레이터 선언

```js
async function* generate() {
  yield await request();
}
```

async 함수의 비동기 처리와 제너레이터의 중단·재개 기능을 함께 가진 함수를 선언한다.

---

#### 클래스 선언

```js
class Product {
  constructor(name) {
    this.name = name;
  }
}
```

클래스 이름에 대한 바인딩과 클래스 정의를 함께 도입한다.

---

#### 선언과 표현식 형태

함수와 클래스는 선언 형태와 표현식 형태를 모두 가질 수 있다.

<table>
  <thead>
    <tr>
      <th>대상</th>
      <th>선언 형태</th>
      <th>표현식 형태</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>함수</td>
      <td><code>function run() {}</code></td>
      <td><code>const run = function () {};</code></td>
    </tr>
    <tr>
      <td>제너레이터 함수</td>
      <td><code>function* generate() {}</code></td>
      <td><code>const generate = function* () {};</code></td>
    </tr>
    <tr>
      <td>async 함수</td>
      <td><code>async function load() {}</code></td>
      <td><code>const load = async function () {};</code></td>
    </tr>
    <tr>
      <td>클래스</td>
      <td><code>class Product {}</code></td>
      <td><code>const Product = class {};</code></td>
    </tr>
    <tr>
      <td>화살표 함수</td>
      <td>별도의 선언 형태 없음</td>
      <td><code>const double = value => value * 2;</code></td>
    </tr>
  </tbody>
</table>

구별 기준은 `function`이나 `class`라는 단어의 존재 여부가 아니라 해당 구문이 놓인 문법적 위치다.

---

#### 바인딩 패턴

선언에서 이름이 들어가는 위치에는 하나의 `BindingIdentifier`뿐 아니라 구조 분해 바인딩 패턴도 사용할 수 있다.

```txt
바인딩
├─ BindingIdentifier
└─ BindingPattern
   ├─ ObjectBindingPattern
   └─ ArrayBindingPattern
```

##### 객체 바인딩 패턴

```js
const { name, age } = user;
```

객체의 프로퍼티에서 값을 추출해 여러 이름에 바인딩한다.

##### 배열 바인딩 패턴

```js
const [first, second] = values;
```

반복 가능한 값에서 요소를 추출해 여러 이름에 바인딩한다.

바인딩 패턴은 객체·배열 리터럴과 외형이 비슷하지만 문법 역할이 다르다.

```txt
const { name } = user;
      └──────── 객체 바인딩 패턴

const object = { name };
               └────── 객체 리터럴
```

바인딩 패턴 자체는 독립된 선언 종류가 아니라 선언, 매개변수, `catch` 바인딩 등에서 이름을 지정하는 구문이다.

---

### 최상위 구문 목표

ECMAScript 소스 텍스트는 최상위에서 `Script` 또는 `Module`이라는 구문 목표로 분석된다.

```txt
최상위 구문 목표
├─ Script
└─ Module
```

구문 목표는 파서가 전체 소스 텍스트를 어떤 최상위 문법으로 분석할지를 결정한다.

---

#### Script

`Script`는 일반적인 스크립트 소스 코드를 분석하는 최상위 구문 목표다.

```js
const value = 10;

function run() {
  console.log(value);
}

run();
```

`Script`는 문과 선언으로 이루어진 `StatementList`를 포함할 수 있다.

```txt
Script
└─ ScriptBody
   └─ StatementList
      ├─ Statement
      └─ Declaration
```

일반적인 Script 최상위에서는 `import`와 `export` 선언을 사용할 수 없다.

```js
import value from "./value.js"; // Script로 분석하면 SyntaxError
```

---

#### Module

`Module`은 ECMAScript 모듈 소스 코드를 분석하는 최상위 구문 목표다.

```js
import { value } from "./value.js";

export function run() {
  return value;
}
```

Module은 일반 문과 선언뿐 아니라 `import`, `export`를 포함할 수 있다.

```txt
Module
└─ ModuleBody
   └─ ModuleItemList
      ├─ ImportDeclaration
      ├─ ExportDeclaration
      └─ StatementListItem
```

Module 코드는 항상 strict mode로 실행된다.

Script와 Module은 단순히 실행 방식만 다른 것이 아니라 허용되는 구문과 식별자 제약도 다를 수 있다.

```js
const await = 10;
```

일부 Script 문맥에서는 허용될 수 있지만 Module에서는 `await` 관련 문법 제약을 받는다.

Module Record, linking, instantiation, evaluation, live binding 등의 실행 의미는 모듈에서 다룬다.

---

## 1.1.3 줄 종결자와 세미콜론

줄 종결자는 일반적인 토큰이 아니지만 구문 문법의 해석과 세미콜론 자동 삽입에 영향을 준다.

```txt
줄 종결자와 세미콜론
├─ [no LineTerminator here]
├─ 제한 문법
└─ 세미콜론 자동 삽입
```

---

### `[no LineTerminator here]`

ECMAScript 문법 생산식에는 특정 토큰 사이에 줄 종결자가 올 수 없다는 제약이 존재한다.

명세에서는 이를 다음과 같이 표시한다.

```txt
[no LineTerminator here]
```

이는 두 문법 요소 사이에 줄 종결자가 존재하면 해당 생산식을 사용할 수 없다는 뜻이다.

예를 들어 후위 증가 표현식은 피연산자와 `++` 사이에 줄 종결자가 없어야 한다.

```js
value++;
```

다음은 같은 후위 증가 표현식으로 해석되지 않는다.

```js
value;
++next;
```

`value++`로 연결되지 않고, 문법적으로 가능한 경우 다음과 같이 분리될 수 있다.

```js
value;
++next;
```

화살표 함수의 매개변수와 `=>` 사이에도 줄 종결자가 올 수 없다.

```js
const double = (value) => value * 2;
```

```js
const double = (value)
=> value * 2; // SyntaxError
```

---

### 제한 문법

제한 문법은 특정 위치의 줄 종결자로 인해 문법 해석이 제한되는 생산식을 말한다.

대표적으로 다음 구문이 영향을 받는다.

```txt
후위 ++와 --
return
throw
break의 레이블
continue의 레이블
yield
async 함수 문법
화살표 함수의 =>
```

---

#### return과 줄바꿈

```js
return;
value;
```

`return`과 반환 표현식 사이에 줄 종결자가 있으므로 `value`는 반환 표현식에 포함되지 않는다.

다음과 유사하게 처리된다.

```js
return;
value;
```

객체를 반환할 때 특히 주의해야 한다.

```js
return
{
  name: "Mars",
};
```

대략 다음과 같이 해석된다.

```js
return;

{
  name: "Mars";
}
```

객체를 반환하려면 같은 줄에서 객체 리터럴을 시작해야 한다.

```js
return {
  name: "Mars",
};
```

또는 괄호로 표현식이 계속된다는 점을 명확히 할 수 있다.

```js
return {
  name: "Mars",
};
```

---

#### throw와 줄바꿈

`throw`와 던질 표현식 사이에는 줄 종결자가 올 수 없다.

```js
throw new Error();
```

다음 코드는 SyntaxError다.

```js
throw
new Error();
```

`return`과 달리 `throw;`라는 문법은 존재하지 않는다.

따라서 줄바꿈 앞에 세미콜론을 삽입하더라도 유효한 `throw`문을 만들 수 없다.

---

#### break·continue와 레이블

```js
break outer;
continue outer;
```

`break` 또는 `continue`와 레이블 이름 사이에 줄 종결자가 있으면 해당 이름은 레이블로 연결되지 않는다.

```js
break
outer;
```

대략 다음과 같이 해석될 수 있다.

```js
break;
outer;
```

`continue`도 마찬가지다.

```js
continue
outer;
```

```js
continue;
outer;
```

---

#### yield와 줄바꿈

```js
yield value;
```

`yield`와 피연산자 사이의 줄 종결자는 문법 구조에 영향을 줄 수 있다.

```js
yield;
value;
```

문맥에 따라 피연산자가 없는 `yield` 표현식과 별도의 `value` 표현식 문으로 해석될 수 있다.

---

#### async와 줄바꿈

`async`와 `function` 사이의 줄바꿈은 문법 해석을 바꿀 수 있다.

```js
async function load() {}
```

다음은 동일한 async 함수 선언으로 해석되지 않는다.

```js
async;
function load() {}
```

첫 번째 줄의 `async`가 별도의 식별자 참조 표현식 문으로 해석될 수 있다.

async 화살표 함수 문법에서도 줄 종결자 제약이 적용된다.

```js
const load = async (value) => value;
```

---

### 세미콜론 자동 삽입

ECMAScript의 많은 문과 선언은 세미콜론으로 끝난다.

```js
run();
const value = 10;
return value;
```

그러나 정해진 조건에서는 소스 코드에 세미콜론이 직접 적혀 있지 않아도 세미콜론이 토큰 스트림에 삽입된 것으로 처리된다.

이를 Automatic Semicolon Insertion, ASI라고 한다.

---

#### 세미콜론의 역할

세미콜론은 표현식을 값으로 만들거나 표현식을 문으로 변환하는 연산자가 아니다.

```js
run();
```

`run()`은 호출 표현식이다.

```js
run();
```

전체는 표현식 문이다.

```txt
ExpressionStatement
├─ Expression: run()
└─ ;
```

세미콜론은 표현식 문의 문법 구조를 완성하는 구두점이다.

---

#### 줄바꿈마다 삽입되는 것은 아니다

줄바꿈이 존재한다고 해서 항상 세미콜론이 삽입되는 것은 아니다.

```js
const result = first + second;
```

하나의 덧셈 표현식으로 이어서 분석할 수 있으므로 중간 줄바꿈에 세미콜론이 삽입되지 않는다.

다음 코드도 하나의 표현식으로 이어진다.

```js
const result = getValue()[0];
```

다음과 같은 구조로 분석할 수 있기 때문이다.

```js
const result = getValue()[0];
```

---

#### 기본 삽입 상황

ASI의 주요 삽입 상황을 단순화하면 다음과 같다.

```txt
ASI
├─ 다음 토큰 때문에 문법 분석을 계속할 수 없는 경우
├─ 닫는 중괄호 앞
├─ 입력 끝
└─ 제한 문법의 줄 종결자
```

##### 다음 토큰 때문에 분석을 계속할 수 없는 경우

현재까지 읽은 토큰과 다음 토큰을 이어 유효한 문법 구조를 만들 수 없고, 둘 사이에 줄 종결자가 존재하면 세미콜론이 삽입될 수 있다.

```js
const first = 10;
const second = 20;
```

다음과 같이 처리될 수 있다.

```js
const first = 10;
const second = 20;
```

##### 닫는 중괄호 앞

세미콜론이 필요하지만 다음 토큰이 `}`인 경우 그 앞에 삽입될 수 있다.

```js
{
  run();
}
```

다음과 같이 처리될 수 있다.

```js
{
  run();
}
```

##### 입력 끝

입력 끝에 도달했지만 세미콜론이 없어 전체 코드를 완성된 문법 구조로 분석할 수 없는 경우 삽입될 수 있다.

```js
run();
```

다음처럼 처리될 수 있다.

```js
run();
```

##### 제한 문법

`[no LineTerminator here]` 위치에 줄 종결자가 있으면 줄바꿈 앞에 세미콜론이 삽입되어 다른 문법 구조로 해석될 수 있다.

```js
return;
value;
```

```js
return;
value;
```

다만 세미콜론을 삽입해도 유효한 문법 구조가 만들어지지 않는 경우에는 SyntaxError가 발생한다.

```js
throw
new Error();
```

---

#### 다음 줄과 이어질 수 있는 토큰

세미콜론 없는 스타일에서는 다음 토큰으로 시작하는 줄을 특히 주의해야 한다.

```txt
(
[
`
+
-
/
```

##### 여는 괄호

```js
value(next);
```

다음과 같은 함수 호출 표현식으로 이어질 수 있다.

```js
value(next);
```

##### 여는 대괄호

```js
value[0];
```

다음과 같은 프로퍼티 접근 표현식으로 이어질 수 있다.

```js
value[0];
```

##### 백틱

```js
tag`template`;
```

다음과 같은 tagged template으로 이어질 수 있다.

```js
tag`template`;
```

##### 덧셈·뺄셈 연산자

```js
value + next;
```

다음과 같은 덧셈 표현식으로 이어질 수 있다.

```js
value + next;
```

##### 슬래시

`/`는 나눗셈이나 정규 표현식 리터럴과 관련된 문맥적 해석 때문에 특히 주의해야 한다.

---

#### for 헤더에는 삽입되지 않는다

```js
for (initialize; condition; update) {
  run();
}
```

`for` 헤더의 두 세미콜론은 구성 요소를 구분하는 필수 문법이다.

ASI는 이 두 세미콜론을 대신 삽입하지 않는다.

```js
for (
  let index = 0
  index < 10
  index++
) {
}
```

위 코드는 ASI로 복구되지 않는다.

---

#### 빈 문과 ASI

명시적으로 작성된 세미콜론 하나는 빈 문이다.

```js

```

그러나 ASI는 아무 위치에나 세미콜론을 삽입하여 빈 문을 만들어 문법 오류를 해결하지 않는다.

```js
if (condition)
else run();
```

`else` 앞에 세미콜론을 삽입하면 `if`문의 본문이 빈 문이 되지만, ASI는 이런 방식으로 코드를 임의로 복구하지 않는다.

ASI는 적당한 곳에 세미콜론을 넣는 기능이 아니라 명세에 정의된 제한적인 토큰 삽입 규칙이다.

## 1.1.4 정적 문법 검사

소스 코드가 어휘 문법과 구문 문법에 따라 분석되었다고 해서 항상 실행 가능한 것은 아니다.

ECMAScript는 구문 분석 결과에 추가적인 정적 규칙을 적용한다.

```txt
소스 텍스트
→ 어휘 문법
→ 구문 분석
→ Parse Node
→ 정적 문법 검사
→ 오류가 없으면 평가
```

정적 문법 검사는 다음과 같이 구분할 수 있다.

```txt
정적 문법 검사
├─ 구문 오류
├─ Early Error
└─ strict mode 문법 제약
```

strict mode 문법 제약은 별도의 완전히 독립된 검사 체계라기보다 많은 경우 Early Error 규칙의 조건으로 적용된다.

---

### 구문 오류

구문 오류는 토큰들이 문법 생산식에 맞는 구조를 형성하지 못할 때 발생한다.

```js
const = 10;
```

`const` 뒤에 필요한 바인딩과 초기화 구조가 없으므로 유효한 `LexicalDeclaration`을 만들 수 없다.

```js
if condition {
  run();
}
```

`if`문의 조건에 필요한 괄호가 없으므로 유효한 `IfStatement`를 만들 수 없다.

```js
function () {}
```

문 시작 위치에서 이름 없는 함수 선언으로 해석하려 하지만 해당 문법 형태가 허용되지 않는다.

구문 분석 단계에서 구조 자체를 만들 수 없으면 `SyntaxError`가 발생한다.

---

### Early Error

Early Error는 소스 코드가 문법 생산식에 따라 구조적으로 분석된 뒤, 실제 평가가 시작되기 전에 적용되는 정적 오류 규칙이다.

```txt
Parse Node 생성 성공
→ 해당 문법 생산식의 Early Error 검사
→ 위반하면 SyntaxError
→ 해당 Script나 Module의 평가 시작 안 함
```

예를 들어 다음 코드는 `const` 선언이라는 문법 구조 자체는 만들 수 있다.

```js
const value;
```

그러나 초기화 표현식이 없는 `const` 선언은 Early Error다.

구문 오류와 Early Error는 외부에서 모두 `SyntaxError`로 관찰될 수 있지만 오류가 규정되는 단계가 다르다.

<table>
  <thead>
    <tr>
      <th>구분</th>
      <th>설명</th>
      <th>예시</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>구문 오류</td>
      <td>문법 생산식에 맞는 구조 자체를 만들 수 없다.</td>
      <td><code>const = 10;</code></td>
    </tr>
    <tr>
      <td>Early Error</td>
      <td>구조는 만들 수 있지만 추가적인 정적 제약을 위반한다.</td>
      <td><code>const value;</code></td>
    </tr>
  </tbody>
</table>

---

#### 중복 어휘 선언

```js
{
  let value;
  let value;
}
```

같은 `StatementList`에서 동일한 이름을 여러 번 어휘 선언하므로 Early Error다.

```js
{
  let value;
  const value = 10;
}
```

이 경우에도 같은 이름을 중복하여 어휘 선언한다.

블록의 `LexicallyDeclaredNames`에 중복 항목이 있으면 SyntaxError다.

---

#### 어휘 선언과 var 선언의 충돌

```js
{
  let value;
  var value;
}
```

같은 범위의 어휘 선언 이름과 `var` 선언 이름이 충돌하므로 Early Error다.

개념적으로는 다음 집합이 겹치는지 검사한다.

```txt
LexicallyDeclaredNames
VarDeclaredNames
```

---

#### 중복 바인딩 이름

```js
let { name, name } = object;
```

하나의 어휘 선언에서 생성되는 바인딩 이름에 중복 항목이 있으므로 Early Error다.

```txt
BoundNames
├─ name
└─ name
```

---

#### 초기화 없는 const

```js
const value;
```

일반적인 `const` 선언에는 초기화 표현식이 필요하다.

```js
const value = 10;
```

처럼 초기화해야 한다.

---

#### 유효하지 않은 할당 대상

할당 표현식의 왼쪽은 값을 저장할 수 있는 유효한 할당 대상이어야 한다.

```js
10 = value;
```

숫자 리터럴은 할당 대상이 아니다.

```js
left + right = value;
```

덧셈 표현식도 할당 대상이 아니다.

```js
run() = value;
```

함수 호출 표현식도 일반적인 할당 대상이 아니다.

---

#### 유효하지 않은 갱신 대상

`++`와 `--`의 피연산자는 갱신 가능한 대상이어야 한다.

```js
10++;
```

```js
(first + second)++;
```

리터럴이나 덧셈 표현식은 값을 저장할 위치를 나타내지 않으므로 갱신할 수 없다.

---

#### break의 문맥

```js
break;
```

레이블 없는 `break`는 반복문이나 `switch`문 안에서만 사용할 수 있다.

유효한 문맥 밖에서 사용하면 Early Error다.

```js
function run() {
  break; // SyntaxError
}
```

레이블이 있는 `break`는 현재 레이블 집합에 존재하는 레이블을 참조해야 한다.

```js
break missing;
```

현재 문맥에 `missing` 레이블이 없다면 허용되지 않는다.

---

#### continue의 문맥

```js
continue;
```

레이블 없는 `continue`는 반복문 안에서만 사용할 수 있다.

```js
function run() {
  continue; // SyntaxError
}
```

레이블이 있는 `continue`는 반복문에 연결된 레이블만 참조할 수 있다.

```js
label: {
  continue label; // SyntaxError
}
```

`label`은 블록문에 붙어 있으며 반복문에 연결된 레이블이 아니므로 `continue`의 대상이 될 수 없다.

---

#### return의 문맥

```js
return value;
```

`return`은 함수 본문처럼 `[Return]` 문법 매개변수가 허용된 문맥에서만 사용할 수 있다.

일반적인 Script 최상위에서는 사용할 수 없다.

```js
return value; // SyntaxError
```

---

#### await와 yield의 문맥

##### yield

```js
function* generate() {
  let yield = 10;
}
```

제너레이터 문맥에서는 `yield`를 일반 바인딩 이름으로 사용할 수 없다.

##### await

```js
async function load() {
  let await = 10;
}
```

async 함수 문맥에서는 `await`를 일반 바인딩 이름으로 사용할 수 없다.

Module 코드에서도 `await`는 일반적인 바인딩 이름으로 제한된다.

식별자 사용 가능 여부는 다음 요소들의 조합으로 결정된다.

```txt
IdentifierName
ReservedWord
Yield 문법 매개변수
Await 문법 매개변수
strict mode 여부
Early Error 규칙
```

---

#### private 이름

클래스에서 선언되지 않은 private 이름을 참조하면 Early Error다.

```js
class Example {
  method() {
    return this.#missing;
  }
}
```

`#missing`은 해당 클래스에서 선언되지 않았다.

private 이름의 중복 선언도 제한된다.

```js
class Example {
  #value;
  #value;
}
```

다만 private getter와 setter의 허용된 한 쌍처럼 명세가 특별히 허용하는 경우는 예외다.

---

#### 정규 표현식 리터럴

```js
const pattern = /[/;
```

어휘 문법에서 정규 표현식 리터럴 형태로 토큰화되더라도 내부 패턴이 유효한 정규 표현식 문법을 만족하지 않으면 Early Error가 될 수 있다.

---

#### Early Error의 범위

Early Error는 하나의 독립된 코드 종류가 아니다.

각 문법 생산식 아래에 해당 구문이 만족해야 할 정적 제약으로 분산되어 있다.

```txt
표현식
├─ 할당 대상의 유효성
└─ 갱신 대상의 유효성

문
├─ break 문맥
├─ continue 문맥
└─ return 문맥

선언
├─ 중복 바인딩 금지
└─ const 초기화 필수

블록
├─ 어휘 선언 이름 중복 금지
└─ 어휘 선언과 var 선언 충돌 금지

클래스
├─ private 이름 선언 확인
└─ private 이름 중복 제한

Script·Module
└─ 최상위 선언과 문맥 제약
```

따라서 Early Error는 문법 분석과 실행 사이에서 코드의 정적 유효성을 검사하는 규칙들의 집합이다.

---

### strict mode 문법 제약

strict mode는 일부 JavaScript 문법과 동작에 더 강한 제한을 적용하는 실행 모드다.

strict mode는 다음과 같은 방식으로 적용된다.

```js
"use strict";
```

함수 본문의 지시문으로 적용할 수도 있다.

```js
function run() {
  "use strict";
}
```

Module 코드는 별도의 지시문 없이 항상 strict mode다.

strict mode에서 발생하는 많은 문법 제약은 Early Error로 규정된다.

---

#### with문 금지

```js
"use strict";

with (object) {
  run();
}
```

`with`문은 strict mode에서 허용되지 않는다.

---

#### eval과 arguments 바인딩 제한

strict mode에서는 일부 위치에서 `eval`과 `arguments`를 바인딩 이름으로 사용할 수 없다.

```js
"use strict";

let eval = 10;
```

```js
"use strict";

function run(arguments) {}
```

이러한 코드는 Early Error다.

---

#### 중복 매개변수 제한

strict mode 함수에서는 같은 매개변수 이름을 중복 사용할 수 없다.

```js
function run(value, value) {
  "use strict";
}
```

중복 매개변수는 함수의 매개변수 형태와 strict mode 여부에 따라 정적 제약을 받는다.

---

#### strict mode와 예약어

strict mode에서는 일부 미래 예약어가 식별자로 제한된다.

```txt
implements
interface
let
package
private
protected
public
static
yield
```

실제 허용 여부는 해당 이름이 놓인 문법 위치와 문맥에 따라 결정된다.

---

## 전체 처리 과정

문법 구조 전체를 하나의 흐름으로 정리하면 다음과 같다.

```txt
1. 소스 텍스트 입력
   │
   ├─ 문자
   ├─ 공백
   ├─ 줄 종결자
   └─ 주석
   │
2. 어휘 문법 적용
   │
   ├─ 식별자 이름
   ├─ 예약어
   ├─ 구두점
   ├─ 리터럴 토큰
   └─ 템플릿 관련 토큰
   │
3. 어휘 목표 기호 선택
   │
   ├─ 나눗셈 문맥
   ├─ 정규 표현식 문맥
   └─ 템플릿 문맥
   │
4. 구문 문법 적용
   │
   ├─ 표현식
   ├─ 문
   ├─ 선언
   └─ Script·Module
   │
5. 줄 종결자·세미콜론 규칙 적용
   │
   ├─ [no LineTerminator here]
   ├─ 제한 문법
   └─ ASI
   │
6. 정적 문법 검사
   │
   ├─ 구문 오류
   ├─ Early Error
   └─ strict mode 문법 제약
   │
7. 오류가 없으면 평가
```

핵심 관계는 다음과 같다.

```txt
어휘 문법
문자를 토큰으로 구분한다.

구문 문법
토큰을 표현식·문·선언 등의 구조로 결합한다.

줄 종결자와 세미콜론
토큰 스트림이 구문 문법으로 분석되는 방식에 영향을 준다.

정적 문법 검사
만들어진 문법 구조가 실제로 허용되는지 평가 전에 검사한다.
```
