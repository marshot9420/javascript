## 분류 기준

```txt
[S] Specification  ECMAScript 명세가 보장하는 것
[H] Host           브라우저나 Node.js가 정하는 것
[E] Engine         V8 같은 특정 엔진의 구현 방식
[C] Computer Science 일반적인 계산·자료구조·시스템 원리
[F] Framework      React, Next.js 등 프레임워크의 규칙
```

예시:

```txt
[S] Promise 반응은 Job으로 등록된다.
[H] 브라우저는 Promise Job을 microtask queue와 결합해 처리한다.
[H] Node.js에는 process.nextTick 전용 큐와 event loop 단계가 있다.
[E] V8은 객체 형태를 추적하기 위해 hidden class와 inline cache를 사용한다.
[C] 큐는 FIFO 자료구조다.
[F] React는 상태 업데이트를 배치할 수 있다.
```

ECMAScript의 실행 컨텍스트와 Job은 명세상의 모델이며, 실제 운영체제 스레드나 물리적 스택과 반드시 일대일로 대응하는 것은 아니다. Promise 콜백이 실행될 때에도 새로운 실행 컨텍스트가 실행 컨텍스트 스택에 들어간다.

브라우저에서는 현재 동기 실행이 끝난 뒤 microtask가 처리되고, setTimeout은 별도의 task로 취급된다. Node.js의 process.nextTick()은 현재 작업이 끝난 직후 event loop가 다음 단계로 진행하기 전에 해당 큐를 먼저 소진한다. 따라서 “JavaScript의 이벤트 루프”를 하나의 보편적인 순서표로 외워서는 안 된다.
