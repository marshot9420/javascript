# 계획

다음 상태에 도달하는 것을 목표로 잡는다.

> **일반적인 JavaScript 코드를 실행 전에 추적하고, 실제 결과가 다르면 디버거·실험·명세를 이용해 원인을 밝혀내며, 핵심 실행 원리를 축소된 형태로 직접 구현할 수 있는 상태**

그다음 12주 동안 엔진, 자료구조, 네트워크, 성능, 웹 프레임워크까지 연결한다.

## 1. 시간 배분

### 기본 학습량

| 구분      |         학습량 | 역할                  |
| --------- | -------------: | --------------------- |
| 월~금     |   오전 75~80분 | 탐구와 실험           |
| 토요일    |     오전 120분 | 통합 구현과 주간 검증 |
| 일요일    | 휴식 또는 20분 | 회고만 수행           |
| 주간 합계 |       약 8시간 | 지속 가능한 최대치    |
| 12주 합계 |      약 95시간 | 1차 실행 모델 구축    |

업무량에 따라 세 가지 모드로 운영한다.

#### 표준일: 80분

```txt
5분   전날 질문과 오늘의 현상 선택
20분  AI·검색 없이 먼저 구현하거나 결과 예측
15분  실행·디버거 관찰
15분  필요한 이론만 조사
15분  가설을 깨뜨리는 변형 실험
10분  탐구 기록과 다음 질문 작성
```

#### 바쁜 날: 40분

```txt
10분  코드 결과 예측
10분  실행과 디버깅
10분  핵심 원인 조사
10분  한 문단 설명과 질문 기록
```

#### 긴급 업무일: 20분

```txt
5분   코드 하나 선택
5분   실행 결과 예측
5분   실제 실행
5분   차이와 질문 하나 기록
```

> 20분 학습도 정상적인 학습일로 인정한다. 부족한 시간을 다음 날 몰아서 보충하지 않는다.

## 2. 요일별 반복 구조

분류 체계의 순서가 아니라 하나의 현상을 일주일 동안 여러 각도에서 해부한다.

| 요일   | 역할            | 완료 조건                                  |
| ------ | --------------- | ------------------------------------------ |
| 월요일 | 최초 도전       | 설명을 보지 않고 먼저 구현하거나 결과 예측 |
| 화요일 | 실행 추적       | 호출 스택·스코프·객체·실행 순서 관찰       |
| 수요일 | 이론과 가설     | 필요한 이론을 배우고 자신의 설명 작성      |
| 목요일 | 반증 실험       | 조건을 바꾸어 가설의 경계 확인             |
| 금요일 | 전이와 알고리즘 | 다른 문제·실무 코드·자료구조에 적용        |
| 토요일 | 통합 구현       | 한 주의 원리를 작은 프로젝트에 반영        |
| 일요일 | 회복과 회고     | 새로운 공부 없이 지도와 질문만 정리        |

### 매주 남겨야 하는 결과물

```txt
작동하는 프로젝트 증분       1개
실행 추적 기록               3개 이상
반증 가능한 실험             3개 이상
자료구조·알고리즘 분석       1개
자신의 언어로 작성한 설명    1개
다음 주로 넘길 미해결 질문   2~5개
```

> 개수가 중요한 것이 아니라, 한 문제를 깊게 해부한다.

## 3. 계획

### 1주차: JavaScript 실행 순서 실험

- 표현식 평가 순서
- `var`, `let`, `const`
- TDZ와 선언 초기화
- 원시값과 객체값
- 공유 참조
- 함수 호출 스택
- 기초 스코프

결과물:

- 실행 순서 예측 문제 12개
- 변수·객체 참조도를 그린 기록 5개
- `var`, `let`, `const` 비교 실험
- 실행 추적 노트 저장소 구축

### 2주차: 함수, 스코프, 클로저, `this`

- 함수 선언과 함수 표현식
- 렉시컬 스코프
- 클로저
- 일반 함수와 화살표 함수
- 호출 방식에 따른 this
- call, apply, bind
- 재귀

결과물:

- `once`, `memoize`, `debounce` 직접 구현
- 축소된 `bind` 구현
- 클로저의 참조 구조를 그린 기록
- 재귀와 반복 구현의 호출 스택 비교

### 3주차: 객체와 프로토타입

### 6주차: 자료구조와 실행 모델

직접 구현한다

- Linked List

결과물:

- 자료구조 4개 이상

- LRU Cache 초안

### 4. 지속성을 지키는 세 가지 규칙

1. 실행하기 전에 반드시 예측한다.
   - 예측하지 않은 실험은 관찰에 머물 뿐이다.
2. 이틀 연속 완전히 끊지 않는다.
   - 업무가 과중한 날에는 20분짜리 최소 순환만 수행한다.
3. 진도를 보충하지 않는다.
   - 밀린 분량을 몰하서 처리하지 않고, 핵심 질문과 프로젝트만 다음 주로 이동시킨다.
